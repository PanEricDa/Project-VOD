# 友方 AI 基础战斗系统设计备档

> 备档日期：2026-07-13  
> 当前状态：仅完成设计，尚未实施攻击行为

## 1. 设计目标

在保留现有伙伴编队、游荡、冲刺追赶和敌人感知逻辑的基础上，为未来的友方 AI 战斗系统确定一套最低限度但完整的行为闭环：

```text
发现或接收目标 → 追击 → 进入攻击距离 → 执行攻击 → 目标失效 → 返回编队
```

目标选择与实际行为状态必须相互独立。目标来源只决定“攻击谁”，行为状态负责决定“现在如何行动”，避免自由模式和玩家管控模式各自复制一套追击、攻击和归队代码。

## 2. 两种目标决策模式

两种模式无需玩家手动切换，而是根据玩家当前是否存在有效锁定目标自动决定。

### 自由行为模式

- 玩家没有有效锁定目标时启用。
- 伙伴从自身感知范围内选择最近的有效敌人作为自主目标。
- 当前自主目标仍有效时保持该目标，不因其他敌人的距离发生小幅变化而频繁切换。
- 只有当前目标死亡、失效、离开允许范围或伙伴被要求归队时，才重新选择目标。

第一版不引入威胁值、敌人职业、剩余生命或危险程度等复杂优先级。最近的有效敌人就是当前阶段的最高优先级目标。

### 玩家管控模式

- 玩家存在有效锁定目标时自动启用。
- 玩家锁定目标拥有最高优先级，可以立即覆盖伙伴当前的自主目标。
- 所有具备攻击能力的伙伴跟随玩家攻击同一个目标，但仍使用各职业自己的攻击距离和站位方式。
- 玩家解除锁定，或者锁定目标死亡、失效、超出允许范围后，伙伴自动回到自由行为模式。
- 玩家锁定不应允许伙伴无限距离追击；超过伙伴自身的追击边界时仍需停止追击并归队。

## 3. 目标来源与行为状态

### 目标来源

建议使用以下目标来源枚举：

```text
NONE            当前没有战斗目标
SELF_SELECTED   由伙伴自身感知系统选择
PLAYER_LOCK     来自玩家锁定，优先级最高
```

目标来源的优先级为：

```text
PLAYER_LOCK > SELF_SELECTED > NONE
```

### 行为状态

建议在现有伙伴行为之上形成以下战斗状态：

```text
FORMATION        使用当前编队、游荡和追赶玩家的行为
CHASE            向当前职业所需的攻击位置移动
ATTACK           已进入有效攻击距离，保持朝向并执行攻击
COMBAT_RECOVERY  目标结束后的短暂恢复，避免瞬间转身
RETURN           停止追击并返回原有编队区域
```

基本状态流转：

```text
FORMATION ──获得目标──> CHASE ──进入攻击距离──> ATTACK
     ↑                    ↑                         │
     │                    └────目标暂时拉开────────┘
     │
     └── RETURN <── COMBAT_RECOVERY <──目标失效或战斗结束
```

玩家锁定目标时只替换当前目标及目标来源；如果伙伴已经在追击或攻击状态，不需要重启整套状态机。

## 4. 基础稳定规则

### 目标有效性

战斗目标必须同时满足：

- 节点仍然有效并处于场景树中。
- 属于敌方阵营或 `enemy_targets` 分组。
- 尚未死亡；生命系统加入前可暂时只检查节点有效性。
- 没有超过最大追击边界。

目标无效后必须清除引用，防止伙伴继续朝已删除节点移动或攻击。

### 追击边界

建议未来提供三个独立参数：

- `attack_detection_range`：伙伴可以自主发现敌人的范围，可复用当前球形感知范围。
- `maximum_chase_distance`：允许伙伴离开玩家或编队中心追击的最大距离。
- `return_to_formation_distance`：触发强制放弃目标并归队的边界。

追击距离以玩家或当前编队中心为基准，而不是以伙伴开始战斗的位置或敌人初始位置为基准。这样玩家离开战场时，伙伴不会长期滞留在远处。

### 换目标稳定性

- 自由行为模式的目标刷新仍可沿用当前约 `0.2～0.4` 秒的低频检查。
- 当前自主目标有效时不主动切换。
- 玩家锁定目标不受该刷新间隔限制，应立即覆盖自主目标。
- 玩家取消锁定后，可以继续攻击仍然有效的原目标，或在下一次目标刷新时选择最近目标；第一版建议直接重新执行一次自由选敌。

### 职业攻击距离

公共 AI 只管理目标、追击边界、状态流转与归队，不硬编码所有职业共用的攻击距离。

- Guardian：近战距离，需要接近目标。
- Ranger：远程距离，保持在敌人后方或侧后方的安全位置。
- Mage：远程距离，并继续与 Ranger 协调分侧，减少站位重叠。
- Healer：当前尚未设计攻击或治疗机制，第一版可以只维持战斗站位而不执行攻击。

各职业后续通过独立攻击模块或子类参数提供期望攻击距离、攻击冷却和具体攻击方式。

### 战斗结束与归队

- 目标失效后进入 `COMBAT_RECOVERY`，建议停留约 `0.2～0.4` 秒。
- 恢复期间停止发起新攻击，但继续应用重力和必要的平滑转向。
- 随后进入 `RETURN`，复用现有编队中心、导航移动和必要的追赶冲刺。
- 回到编队允许区域后恢复 `FORMATION`，重新开始原有游荡逻辑。

## 5. 第一版推荐规则

1. 玩家锁定有效敌人时，所有具备攻击能力的伙伴使用该目标。
2. 玩家没有锁定时，伙伴选择自身感知范围内最近的敌人。
3. 自主目标有效期间不主动换目标。
4. 玩家锁定可以立即覆盖自主目标。
5. 每个职业独立配置攻击距离，但共享目标管理、追击边界和归队规则。
6. 目标死亡、失效或追击过远后停止攻击，短暂恢复并返回编队。
7. Healer 在其职业机制确定前，可以只进入战斗站位而不执行攻击。

这套规则是当前阶段建议保留的最低限度。目标稳定、追击边界和归队逻辑不建议继续删减，否则容易产生反复换目标、无限追敌或战斗结束后无法归队的问题。

## 6. 暂不实施的内容

本备档不代表以下功能已经完成：

- 敌我生命值、伤害结算、死亡、击退和硬直。
- Guardian、Ranger、Mage、Healer 的具体攻击模块和动画表现。
- 仇恨值、威胁评分、敌人职业优先级和残血目标优先。
- 视线遮挡、视野角度和复杂感知规则。
- 多伙伴攻击位置预约、集火人数限制和防止包围重叠。
- 玩家对单个伙伴下达命令。
- Healer 治疗、Guardian 保护等职业战术。

## 7. 实施边界与项目规则

- 后续实现应优先扩展 `AllyBase` 的通用目标与状态接口，职业攻击方式保留在子类或可拆装攻击模块中。
- 不应破坏当前伙伴编队、分侧、随机游荡、追赶冲刺、敌人感知和重力行为。
- 玩家锁定目标应复用 `HeroController.locked_target_changed` 信号，不重复编写另一套玩家目标检测。
- 任何玩家、友方、敌方或其他单位实例需要加入 `res://Scenes/TestScene.tscn` 时，必须由用户在 Godot 编辑器中手动添加。Codex 只提供场景文件、父节点、初始位置和必要 Inspector 参数的指引。
