# 技能动画位移组件设计

日期：2026-10-20。状态：用户已确认设计与实施计划；四任务已实施并完成独立复核、真实运行验收。

## 目标与约束

为Archer终结技增加随后翻发生的水平后退；初始距离0.8米，保持瞄准朝向。
技能场景负责配置，动画方法帧负责启停，已有单位物理循环负责碰撞移动。
时间必须与当前动作统一：不得硬编码5%/20倍补偿，不维护独立的0.45秒倒计时，不复制动画播放速度参数。
不新增真实腾空、无敌、穿墙或额外伤害；CharacterRoot的起伏翻转保留原动画。

本扩展涉及技能、动画事件和单位移动之间的通用接口，按接口级设计审阅后再规划实施。

## 方案选择

1. 组件独立填写时长、动画另设关键帧：容易重复维护，不能保证修改动画后仍一致，不采用。
2. 使用同一SkillExecutionClock但保留独立时长：可同步慢放，但还需同步动画速度和帧位置，不采用。
3. **采用：动画位移区间与实时动画进度是唯一时间依据。** 组件仅配置方向与距离，无速度和时长字段。

## 策划装配

- 通用节点场景：res://SkillSystem/03-Extensions/SkillMotionComponent.tscn。
- 通用脚本：同目录SkillMotionComponent.gd，继承Node，不继承SkillEffectBase。
- 在需要位移的SkillBase场景下实例化一个组件；本轮只支持单个组件、单个位移区间，不引入编号映射。
- Inspector仅两个内容参数：Direction（自身水平前/后/左/右）及Distance M（米，有限且大于0）。
- Archer首版设为后退、0.8米。方向在区间开始时根据角色稳定的水平朝向锁定，不取翻转中的CharacterRoot朝向。
- 没有挂组件的技能保持现状；直接触发而没有角色动画的技能不会凭空产生位移。
- 不新增外部tres/res或第二套技能执行框架。

## 动画方法轨道

CharacterAnimationPlayer提供无参数事件方法，沿现有信号桥转发：

- begin_skill_motion()：放在起跳开始帧。
- end_skill_motion()：放在落地帧。

一对方法帧定义区间；不在方法参数内填写距离、秒数、技能路径或角色名称。
release_action与finish_action维持原有含义，不能拿它们代替位移区间边界。
本轮应按当前片段的起跳预备至落地缓冲位置放置，候选约0.92至1.46秒；这些秒数只存在于可编辑的动画关键帧中，运行代码不写死。
因此此前讨论的0.45秒是节奏参考，不再成为需要独立维护的组件参数。

挂组件时要求当前动作有且仅有一对位移标记，且0 <= begin < end <= 片长；缺少或倒置时给出明确配置错误，不用隐式默认时间掩盖问题。
不带组件的旧片段不会因没有这些标记而失效。
工作台方法桥不连接战斗执行者时只发信号，不移动预览根，也不报错。

## 数据流与职责

当前动作驱动读取实际播放的Animation及实时游标
→ 以当前request_id转发位移事件/本帧进度
→ SkillHost定位当前活动技能及其SkillMotionComponent
→ 组件计算本帧所需水平位移
→ AIUnitBase在其唯一物理移动循环中执行碰撞移动。

- 动画事件播放器不访问技能路径，也不直接写单位位置。
- SkillHost使用活动动作请求身份；已经释放的技能仍可在后摇期间发起位移，不依赖技能是否仍处于CASTING或投射物是否还在飞行。
- 动作驱动提供动画区间与游标，不要求组件跨模块查找AnimationPlayer内部节点。
- 组件不自行调用move_and_slide，不启动另一条角色物理处理回调。
- 当前AI已有碰撞位移可以复用，但必须适配保持朝向及动作进度驱动，不能原封不动使用会转向位移方向的request_attack_motion。
- 本帧动作推进/位移意图提交须先于单位碰撞移动；实施计划明确处理顺序，不依赖偶然的节点回调先后。
- 单位每物理帧仍只执行原有一次move_and_slide，重力与其他单位保持原处理方式。

## 统一进度与慢放

设动画中位移起止位置为a、b，当前实际动作游标为t：

p = clamp((t-a)/(b-a), 0, 1)
本帧请求位移 = 锁定的水平单位方向 × 配置距离 × (p本帧-p上帧)

p使用动画实际游标，而不是重新累计墙钟秒数。
动画继续通过当前请求的SkillExecutionClock.get_action_delta推进；位移不重复读取或补偿Engine.time_scale。
所以施法速度改变、镜头暂停、5%慢放以及命中后恢复正常速度时，位移与动作自动一起推进或停止。
物理层如需将本帧位移换算为velocity，只使用当前实际物理delta；delta为0或真暂停时不移动，不硬编码流速倍率。
同一请求内不得重复推进位移。跳帧跨过结束标记时先消费最后一段有效进度，再释放位移，不能丢失末段。
首版采用线性距离进度，不暴露额外曲线或加速度参数。

## 碰撞、行动与生命周期

- 区间内仅覆盖普通导航的水平移动意图，不将角色转向后方；结束后恢复原AI决策。
- 碰到障碍按既有物理碰撞截短，不强行补足距离，不跨墙重试。
- 角色腾空外观仍只由动画提供；实际单位物理根只做水平位移。
- 死亡、当前动作取消、离开世界或组件卸载时清理本请求的位移，不能清掉之后新请求的位移。
- 仅停止动作所属位移，不撤销已经发出的箭矢和已经发生的伤害。
- 终结镜头/慢放仍由原导演根据主命中特效结束，不因位移延长慢放；剩余后翻与位移继续跟随同一个动作游标。
- 普通移动和没有位移组件的技能不改变行为。

5. 验证无障碍后退0.8米、保持朝向、撞墙缩短、导航不竞争、取消/死亡不残留。
6. 验证不同世界流速、不同动画播放速度、镜头冻结及区间中途恢复1倍世界速度；在相同动画进度处，累计请求距离相同。

8. 验证正常技能、原攻击位移、终结箭矢单次伤害、后摇完成和世界时序不回归。

验收以真实碰撞后位置、角色朝向、当前动画进度及请求归属为依据，不只检查信号或配置数值。
