# 爆发连携系统完整设计

> 日期：2026-10-11。\
> 状态：汇总已确认玩法，并给出与现有代码对接的架构建议，供书面审阅；不是实现计划，不代表已经实现。\
> 范围：玩家主动技能、伙伴常规行动、实时连携、专注、伤害评分、限时终结选择与终结演出。\
> 本文取代旧讨论记录中的预编排、施放续窗、常规冷却重置及末位自动终结方案。技能装配来源与平衡数值不在本轮定案范围内。

## 1. 体验目标与基本职责

游戏是五人小队的单机即时战斗。玩家组织战场，四名 AI 伙伴处理战场；技能搭配、站位、聚怪、威胁判断与释放时机构成主要决策。

- 玩家技能侧重接管仇恨、引导怪物移动、聚怪、调整阵地，也可以直接攻击或控制。
- 伙伴常规技能承担承伤、输出、控场、治疗与保护，由 AI 自主使用。
- 伙伴连携技能是玩家实时指挥的独立技能内容，不参加常规 AI 自动选技。
- 终结技是达分后获得的一次选择机会，有独立的暂停、演出与释放结算流程。
- 不以精准闪避、格挡为基本生存要求；Dash 属于行动，用于局部避险与站位辅助。
- 怪物继续按已有仇恨、攻击距离与战斗规则行动，不增加专用聚怪状态或仇恨权级。
- 相似职业的玩家版本与伙伴版本可以承担不同职责，不要求技能表完全一致。

独立连携内容不等于独立技能底层：SkillBase、Delivery、Effects、投射物和数值结算继续共用。

## 2. 输入与装配职责

| 内容 | 输入或来源 | 当前设计 |
| --- | --- | --- |
| 玩家主动技能 | Q、E | 两个技能槽，按技能需求使用单位、位置、方向或自身输入 |
| 伙伴常规技能 | AI 自主决策 | 保留现有两个常规槽，不占玩家指挥按键 |
| 伙伴连携技能 | 1、2、3、4 | 每个键对应一个伙伴的连携技能入口；本版每伙伴一个连携槽 |
| 终结选择 | 终结选择窗口内的 1、2、3、4 | 对应四名伙伴的终结选项 |
| 快速锁定 | 现有 F 动作 | 快速选择最近合法敌人 |
| 精准锁定 | 现有鼠标中键动作 | 按屏幕位置选择敌人 |

所有输入通过 Godot InputMap，不在逻辑脚本中硬写物理键。手柄与重绑定映射后续配置到相同动作，不新增另一套玩法。

不使用 Tab 预编排、技能翻页或八选项菜单。玩家在战斗中直接调用伙伴，观察实际出手与伤害后决定下一次输入。

技能与角色绑定、自由装配、职业限制、稀有角色专属、招募随机生成等留到后续系统设计；本版只建立明确槽位与调用边界，不把具体技能 ID 写进角色脚本。

## 3. 两条相互独立的流程

### 3.1 连携技能调用流程

```text
玩家输入
→ 检查角色资格、指令缓存与可用专注
→ 受理、预留专注并显示反馈
→ 等待本伙伴的最早合法行动衔接点
→ 按当前规则确定目标并开始技能
→ 成功释放：提交费用；失败：归还预留
→ 动作结束，伙伴继续处理缓存指令或正常 AI 行为
```

“受理”“开始动作”“成功释放”“实际命中”“动作结束”是不同事件，不能混用。

### 3.2 伤害连携评价流程

```text
本轮第一笔有效连携伤害结算
→ 计入连击与伤害，开启伤害间隔倒数
→ 后续有效连携伤害：计分并刷新倒数
→ 连续超过配置间隔没有新伤害：关闭本轮评分
├─ 未达分：回到普通评价阶段
└─ 达分：检查终结选项
   ├─ 无有效选项：提示并恢复普通战斗
   └─ 有有效选项：暂停，进入限时终结选择
      ├─ 超时：放弃资格，恢复普通战斗
      └─ 选择有效角色：终结接管、演出、释放点结算，恢复普通战斗
```

伤害窗口不监督技能流程，不等待投射物、碎片或所有待执行请求结束。技能成功释放不等于开启或刷新评分窗口。

## 4. 行动优先级与指令缓存

### 4.1 实时连携接入

1. 角色的存活、控制、目标与动作合法性始终有效。
2. 连携请求立即受理并反馈，优先占据下一次合法行动机会。
3. 尚未开始的普通技能决策、普通跟随与接近行为可以让位给连携。
4. 已开始的普通攻击或施法不主动截断；完成本次动作后再连携。
5. 等待连携时，不允许新的自动行动持续抢占机会。
6. 不等待已发出攻击命中、持续效果结束或普通技能冷却结束。
7. 没有待执行指令的伙伴继续正常自主行动，不全队停机。

伙伴独立执行，不建立全队串行队列。先按 1 再按 2，不保证伙伴 1 先释放；玩家可以观察伙伴 1 实际释放，再输入 2，主动掌握节奏。

### 4.2 单伙伴缓存

- 每名伙伴最多一条尚未执行的连携请求；正在执行的技能不是额外的缓存槽。
- 正在释放连携时，可以受理并预留一次后续请求。
- 缓存已满时拒绝新请求，不静默覆盖、不追加长队列、不重复预留费用。
- UI 区分“正在施放”“待执行”和“不可用”，不能把等待误显示为冷却。
- 请求等待必须有有限的执行边界；具体等待参数后续调试。失效、死亡或最终无法接近等通过统一失败路径清理。

### 4.3 连携动作锁定

连携动作开始后，普通 AI、其他技能请求、玩家换锁定都不能主动覆盖其流程。死亡、控制、目标失效等不可抗力遵循技能合法性规则处理。

“没有技能冷却”不意味着同一角色可以同时播放多个动作。当前动作结束，才允许开始同角色下一次连携。

终结接管是单独阶段，见第 9 节；它不是普通连携动作的取消入口。

## 5. 目标选择

目标只是方便执行技能，不是连携窗口的绑定对象，也不影响是否能累计其他敌人的连携伤害。

- 对适用的进攻技能，优先采用玩家当前锁定的合法敌人，不进入加权评分池与其他敌人竞争。
- 没有锁定或锁定不适用时，沿用 AI 与技能自身的目标策略。
- 单体攻击以该目标执行；目标中心范围攻击围绕该目标展开；方向攻击朝该目标释放。
- 治疗、保护与自身范围技能使用自己的友方或自身规则，不强行使用敌人锁定。
- 多目标扩展、分裂与附加目标继续由既有技能规则处理，不由连携管理器代选每个子目标。
- 缓存指令不提前冻结目标；下一次技能即将执行时读取当前锁定与候选。
- 当前目标死亡时，沿用相同目标规则重新选择合法目标，不增加连携专属目标机制。
- 已开始动作的指向更新、跟踪投射物的追踪能力由技能自身决定；玩家换锁定不覆盖正在执行的动作或已发出的攻击。
- 无合法目标或最终不能执行时，请求按普通失败路径结束；不虚构命中、不无限追击。

不改写 AI 的持续锁定，不改动仇恨。伙伴可以转向或接近本次技能目标，结束后仍按自身 AI 规则行动。

玩家技能可以有手动落点和方向输入；伙伴无需额外地板选择。范围、角度、射程由技能配置决定，操作可以宽容，规则和特效反馈必须明确。

## 6. 专注与费用

### 6.1 积累来源

专注由玩家与伙伴常规战斗的有效伤害积累，不按时间自动恢复。大量敌人带来更快恢复，支持高风险、高回报与多轮爆发节奏。

连携与终结伤害不携带专注收益。伤害来源及收益属性在统一数据中表达，消费者按属性处理；不因为迟到、超时或是否计分临时改写来源。

初始值、容量、分格表现及伤害换算公式后续确定，不把旧的示意值当正式数值。

### 6.2 无冷却的连携

- 连携不检查自身技能冷却，也不等待公共行动冷却；专注限制投入，动作流程限制出手。
- 连携请求仍遵循控制、存活、技能目标、条件与动作合法性。
- 普通 AI 技能继续使用原有冷却，不清零或重置常规技能的冷却来伪装连携可用。
- 普通行为的公共冷却和连携动作占用应分开表达；不得用跳过公共冷却顺便跳过当前动作。

### 6.3 预留、提交与退款

| 时点 | 资源处理 |
| --- | --- |
| 请求未受理 | 不预留、不扣除 |
| 请求受理并缓存 | 预留足额专注，防止多个伙伴超额承诺 |
| 技能成功释放 | 提交本次费用 |
| 释放前取消或失败 | 原额归还未提交预留 |
| 已释放但打空或迟到 | 不退款，仍是已执行的连携技能 |

预留、提交与退款属于同一请求的资源生命周期，必须幂等；重复回调不能重复扣费或重复退款。

### 6.4 重复使用

计数单位为“伙伴实例 + 技能”，统计本轮此前成功释放次数，不要求相邻；失败不增加次数，下一轮重新计算。

新轮费用计数从零开始，不等于立即销毁仍有旧请求引用的记录。已受理请求保留原轮次归属，不能因为执行较晚被算作新轮重复；旧记录只作这些请求的费用结算与清理使用，不再开放评分。

```text
本次费用 = 基础费用 + 本轮此前成功释放次数 × 重复附加费用
```

因此 A → B → A 中第二个 A 仍加价。基础费用与附加费用由技能配置，具体数值后续平衡。

缓存可能早于上一技能释放：执行层需要用实际成功记录确定最终费用，并确保预留足够；失败的前序请求不能被算成成功重复。缓存期间展示的是预计费用，不能执行时隐性超额扣款。具体预算实现应在实现计划中落实，而非新增玩家操作。

原方案中的特定组合费用减免不是本版必须内容，待重复计价与实时体验验证后再设计；不能按旧的预编排方式自动加入。

## 7. 伤害间隔窗口与归属

### 7.1 开启和刷新

- 第一次实际造成正伤害时，先把这笔伤害计入本轮，再开启窗口。
- 每笔属于当前开放轮次的有效连携伤害，累计评分并刷新间隔倒数。
- 按键、缓存、施法、成功释放、打空、治疗、增益与纯位移都不刷新倒数。
- 本轮没有伤害超过配置间隔，即结束并结算；没有整轮总时限。
- 连携技能及其衍生效果不提供持续伤害；投射物、碎片、即时范围与多段伤害可以参与。
- 同时命中多个目标按实际有效伤害事件累计，不按敌人数抬高本轮门槛。

接续计时使用正常战斗时间。终结选择倒数使用独立于普通战斗暂停的时间；两者不是同一个计时器。

### 7.2 超时后的统一结果

评分窗口关闭不会取消已受理请求，也不会中断已开始动作。它们继续执行并正常消耗专注。

其迟到伤害仍正常扣血，但不能进入已关闭轮次，也不能自动开启新一轮。来源仍是连携，不因为“普通扣血”而获得专注收益。

新的调用所产生的第一笔有效伤害可以开启新一轮。旧投射物、旧缓存请求及其碎片不能混入新轮。

这些结果由两个基础条件推导：伤害的来源/收益属性未改变；对应评分轮次已经关闭。禁止在每个技能中分别编写“迟到不计分”“失败不回充”等补丁。

### 7.3 必须保留的技术归属

每次请求及其衍生交付需要独立身份，伤害需要携带来源用途与轮次归属。不能用当前角色技能、当前锁定敌人或当前是否有窗口推测归属。

第一笔伤害前也可能有多个已受理请求：技术上可以先建立未开放的轮次归属与费用记录，但不能因此显示或启动伤害倒数。若该批请求自然结束且始终没有正伤害，清理未开启的记录即可；该清理不能触发评分、终结或延长评分窗口。

这属于请求与交付数据的生命周期，不是让评分管理器重新监督施法。其实现需防止长期保存永远未开启的批次，以及未命中请求跨轮污染费用。

## 8. 评分模型

设 H 为本轮有效伤害事件次数，D 为实际伤害总量，H0 与 D0 为大于零的换算尺度：

```text
S = 100 × (H / H0 + D / D0)
S ≥ 100：获得本轮一次终结机会
```

每笔 d > 0 的有效伤害：H 增加 1，D 增加 d；两项贡献相加，没有必须同时满足的双门槛，也没有单项封顶或连击收益衰减。

- 范围攻击对五个敌人各造成一次有效伤害，计五次；实际多段逐次计入。
- 使用实际扣血量，不使用面板伤害或过量击杀伤害。
- 同一目标同一次命中的元素拆分、多个监听回调不能偶然制造重复计分；由统一命中/伤害事件契约确定粒度。
- 治疗、增益与纯位移不计分，但可以正常使用连携技能。
- 玩家 Q/E、普通攻击和 AI 常规技能不计本轮评分；其收益可帮助聚怪、铺设状态或恢复专注。
- 投射物、碎片与即时追加效果继承对应请求归属，而不是被误归为新的常规攻击。
- 满分可以提前提示“终结就绪”，但不立即暂停；仍等伤害间隔超时后进入选择。
- 终结效果不续窗、不重新取得终结资格，也不回充专注。

H0、D0 的章节/难度数值后续调试，不能把旧的 40 次与 2000 伤害示例当正式配置。护盾或未来反应系统应接入统一实际伤害事件契约，不在连携系统里补独立计算。

超时判定与伤害接收使用一致的结算时间基准；同帧事件与边界处理必须确定，不能因 UI、物理与监听回调的先后差异让旧轮次重新开放。

## 9. 终结选择、接管与演出

### 9.1 选择资格

评分结束且达标后，当前暂允许全队有效伙伴提供终结，不要求参与本轮连携。仅参与者可选、末位角色固定终结等保留为后续玩法方向，当前不写死。

- 终结不额外消耗专注，一轮达分提供一次机会。
- 死亡、相应控制、未装备终结等不满足正常施放条件的选项灰显。
- 终结可以覆盖普通动作，但不绕过沉默、眩晕等适用限制。
- 四名伙伴都无可用终结时，跳过选择窗口，提示“当前无可用终结技”，恢复战斗；资格不保留。

### 9.2 限时选择

- 普通战斗暂停，1—4 改为选择终结，不再接收连携或玩家 Q/E 请求。
- 明确显示倒数与灰显原因；选择倒数在暂停期间正常运行，具体时长为后续配置。
- 灰显输入不执行、不消耗资格，也不刷新倒数。
- 超时不自动代选，关闭窗口、放弃本轮资格并恢复战斗。
- 窗口进入前的按键不得穿透为终结选择；按键保持或自动重复不得造成双重操作。

### 9.3 直接接管

有效选择后，终结直接接管该角色，不等待其普通动作自然结束。

- 中断当前行为及其活动技能请求，清理动作锁；被中断请求的未提交预留按统一取消路径归还。
- 不因选择终结顺便清空后续缓存。未被接管中断的缓存请求在恢复战斗后继续按原规则处理，仍保留其原轮次归属；其他伙伴的已受理请求同样保留。
- 已成功释放的攻击与效果不回滚，既有冷却不重置。
- 暂存的普通动作不在演出结束后恢复半截；角色恢复正常决策。
- 角色资格在正式接管前再验证，不能只凭 UI 显示状态结算。

### 9.4 暂停与释放点

终结是独立演出阶段，但复用统一的数值与效果结算。

1. 演出期间玩家、普通 AI、敌人、普通投射物与普通战斗计时冻结。
2. 终结镜头、动画、特效与释放演算独立推进，不能等待被暂停的普通动作或普通物理投射物回调。
3. 释放点对技能规定的合法目标/范围完成主要伤害、治疗、位移或增益结算。
4. 成功释放后立即恢复普通战斗与移动，不等待残留视觉表现结束。
5. 后续视觉投射物或爆炸不再二次交付已结算的主要效果。

暂停不是全场必中。目标关系、覆盖范围和角色资格仍明确；确定性来自冻结期间完成主要效果，而不是忽略技能规则。

演出取消、资源缺失、场景退出等异常路径必须释放暂停、镜头与动作接管，不得卡死战斗或重复使用资格。具体技术恢复路径由实现计划与测试覆盖，不新增一个异常时重复弹窗的玩法。

## 10. UI 最小交付

| UI | 必须表达的内容 |
| --- | --- |
| 玩家技能入口 | Q/E、技能图标与正常可用状态 |
| 伙伴连携入口 | 1—4、伙伴和技能图标、当前预计费用、施放/缓存/不可用反馈 |
| 专注槽 | 当前量、预留量、实际可用量，足够与不足清楚区分 |
| 连携反馈 | 连击数、统一终结进度、伤害间隔倒数；伤害到来时刷新反馈 |
| 终结选择 | 四个伙伴终结选项、独立选择倒数、不可用灰显与简短原因 |

不要求玩家阅读评分公式或多个同级菜单。没有技能冷却的连携入口不能显示伪造的 CD 倒数。

UI 读取公开状态并发送意图，不计算费用、不改变伤害、不拥有暂停恢复逻辑。InputMap 根据当前操作阶段路由，避免相同 1—4 同时触发两个系统。

## 11. 与现有框架对接的架构建议

本节是需要书面审阅的代码结构建议，不是已经实现的内容，也不要求按职责数量机械拆出同等数量的文件。

### 11.1 已有内容与真实缺口

| 已有模块 | 可复用内容 | 本版所需扩展 |
| --- | --- | --- |
| SkillHostComponent | 常规槽、终结槽、动作中介、释放信号 | 连携槽、单条缓存、按请求用途区分冷却门禁与动作占用 |
| SkillBase / SkillContext | 统一激活、条件、消耗、动画释放、运行时上下文 | 连携用途、来源属性、请求/轮次归属；缓存执行时目标解析 |
| AllyBehaviorStateMachine | 接近、转向、外部技能动作、公共冷却 | 待执行连携的行动优先级，不清空正常战斗冷却 |
| PlayerTargetingComponent | 玩家锁定结果与 F/鼠标中键输入 | 作为指令目标提供者复用，不新建指挥锁定 |
| Delivery / Effects / TriggerSkillEffect | 投射物、分裂、多目标、数值效果 | 来源与归属向子交付传播，不另造连携伤害组件 |
| CombatValueResolver / UnitBase | 实际扣血与治疗、统一仇恨 | 统一伤害事件提供用途、收益属性、归属及去重身份 |

当前 Host 门禁检查公共冷却与活动技能，SkillBase 激活也要求就绪；直接调用现有 request_skill 不能自动实现无冷却连携与单条缓存。

当前 UnitBase.damaged 只提供实际伤害和来源节点，不能据此分辨同一角色的常规、连携和终结伤害；不能直接监听它就宣称归属已经完整。

### 11.2 建议职责边界

- 队伍专注管理：接收带收益属性的常规伤害，管理容量、预留、提交与退款。
- 连携控制：路由伙伴输入、保留请求归属与费用记录，接收有效连携伤害，维护伤害窗口与评分。
- 角色技能执行：Host 与行为层处理单条缓存、目标、动作许可、取消和释放事件。
- 终结导演：限时选择后的角色接管、暂停、镜头/演出、释放点交付与恢复。
- UI：显示这些公开状态，不替代执行或结算。

不为每个连携技能写一个管理器，不为每种迟到/失败建立一套特殊规则。使用同一伤害事件，专注与评分根据不同职责消费数据。

### 11.3 请求用途与执行方式不要混淆

现有 CHARACTER_ACTION / DIRECT_TRIGGER 表示通过角色动作还是直接触发交付，EXPLICIT / AI_AUTOMATIC 表示意图来源。

普通、连携、终结属于调用用途，不应通过把连携全部标为 DIRECT_TRIGGER 来绕过动作，也不应通过在全局清零技能冷却来绕过门禁。

连携照常经过角色动作；触发子技能照常走触发交付，但继承父请求伤害归属与收益属性。终结由专用导演调度，在冻结阶段使用可靠的释放点交付。

## 12. Inspector 与 FileSystem 组织建议

遵循 AGENTS.md 的人类可管理原则：配置入口明确、中文说明、强类型引用、高聚合，不要求策划维护隐藏权重或跨文件同步同一参数。

### 12.1 Inspector 建议入口

| 配置位置 | 建议展示内容 |
| --- | --- |
| 伙伴 SkillHost | 常规技能数组、一个连携技能引用、一个终结技能引用 |
| 连携 SkillBase 的费用分组 | 基础专注费用、重复附加费用；动作、目标、Delivery、Effects 沿用既有位置 |
| 队伍连携控制节点 | 四个稳定的伙伴入口、伤害间隔秒数、H0、D0 |
| 队伍专注管理节点 | 容量、初始量、后续确定的常规伤害恢复配置 |
| 终结导演节点 | 选择限时秒数、镜头恢复与通用演出入口 |
| 具体终结技能 | 效果目标规则、主要效果、演出资源及明确的释放点 |

配置用途由槽位与受理入口表达，不靠 ai_priority 极低或名称前缀来决定运行逻辑。收益属性统一注入并向衍生伤害传播，不要求每个子碎片再填一次“零回充”。

除具体技能演出参数外，不给每个终结重复配置同一选择时长，不给每个技能重复配置同一评分门槛。

## 13. 数值与后续范围

### 13.1 后续调试的数值

伤害间隔、指令有限等待、终结选择时间、专注初始值/容量/恢复公式、基础费用/重复费用、评分尺度与各技能数值。这些是明确职责的可配置值，不是需要另外增加的玩法规则。

### 13.2 不在本版定案范围

- 技能获取、装配限制、角色绑定、招募随机与稀有度。
- 仅参与角色可终结或末位固定终结；当前暂按全队有效角色可选。
- 连锁费用减免、连携持续伤害、自由地板指挥与精准时机 QTE。
- 新的仇恨权级、专用聚怪状态或繁复援护菜单。
- 各职业最终连携与终结技能内容、完整镜头和美术制作。

不能把这些后续方向作为首版必须依赖，也不能把建议中的模块结构当已实现或已批准的具体文件清单。

## 14. 验证清单与设计自检

### 14.1 操作与执行

- Q/E、1—4 和终结阶段输入互不穿透，InputMap 可重绑定。
- 伙伴独立出手；观察一次成功释放再调用另一角色可以控制实际节奏。
- 忙碌时指令立即反馈；缓存上限一条，超额输入不覆盖、不重复预留。
- 连携不等普通冷却，但不覆盖已开始动作；普通 AI 不抢占待执行连携。
- 连携开始后没有主动取消覆盖，外部失败只清理该请求，不关闭伤害窗口。
- 缓存执行时使用当前目标策略，换锁定不覆盖已发出攻击。

### 14.2 资源、伤害与窗口

- 常规有效伤害恢复专注，多目标提供更快积累；连携/终结及其衍生伤害无收益属性。
- 并发请求不能超额预留；成功扣费、失败退款均恰好一次。
- 重复加价按同伙伴同技能实际成功记录，不要求相邻，不计失败。
- 第一笔正伤害开启并计入窗口；按键、释放与治疗不续窗。
- 主弹、碎片与多目标事件正确计入，普通伤害不混入。
- 没有连携持续伤害；伤害间隔超时立即结算，不等待全部交付结束。
- 旧缓存请求及旧投射物继续执行但不计分、不续窗、不回充、不串入新轮。
- 超时边界与同帧多笔伤害处理顺序确定，不能既关闭又被旧事件重新开启。

### 14.3 终结与恢复

- 达分且有有效角色才弹窗；全不可用跳过，灰显输入无效果。
- 暂停时选择倒数继续；超时不代选、不保留资格。
- 终结能中断当前动作，但不绕过正常控制或死亡限制。
- 演出使用独立推进，不等待被冻结的动作与投射物。
- 主要效果在释放点准确结算一次，立即恢复移动，残留 VFX 不二次伤害。
- 场景切换、演出失败与节点销毁都恢复暂停和镜头，不留动作锁或资源预留。

### 14.4 结论

当前核心规则已形成闭合：技能调用依据专注与动作规则，伤害窗口依据来源与间隔，终结依据评分与限时选择。原方案中“预编排保证顺序”“施放续窗”“等待所有伤害结束”等规则不能再混入实现。

书面审阅仍需核对架构建议，特别是伤害事件归属、首发未命中批次清理、缓存费用预留与终结暂停生命周期；这些应通过一致的数据契约解决，而非向玩家增加操作或为单个技能添加特例。

本文仅交付设计文档。下一阶段应据此编写实现计划，明确文件交付、接口变更、配置步骤与测试，不直接跳入代码实施。
