# 爆发连携系统四阶段实施路线

> For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans for an approved stage plan. Do not execute this roadmap as one large task.

**Goal:** 通过四个独立验收与 review 的阶段，实现专注驱动的实时伙伴连携、伤害间隔评分和限时终结系统。

**Architecture:** 共用现有 UnitSystem、SkillSystem、Delivery 与 Effects。先建立伤害归属和专注资源，再接入角色请求；伤害评价与技能执行独立，终结导演最后接入暂停和接管。

**Tech Stack:** Godot 4.7、GDScript、InputMap、SceneTree 契约测试、Godot MCP Pro。

**Spec:** [爆发连携系统完整设计](../../Vestiges%20of%20the%20divine/爆发连携系统设计-2026-10-11.md)。

## Global Constraints

- 遵循项目根 AGENTS.md：Godot MCP Pro 编辑优先，Inspector 中文说明，FileSystem 分类清晰。
- 独立技能内容不等于独立执行系统，复用既有数值、仇恨、动画、Delivery、Effects。
- 不向 `res://Scenes/TestScene.tscn` 自动添加或修改单位实例。
- 不覆盖未提交的既有工作，不为测试擅自更改已确认技能参数。
- 正式外部资源必须由 Godot 保存并验证有效 UID 与强类型索引。
- 玩家 Q/E 的输入与动作适配另立小计划，不塞进这四阶段；不扩展自由地板瞄准或玩家职业技能内容。
- 不新增技能获取、随机招募、职业装配限制、稀有度、连锁费用减免或持续伤害连携。

## Review Focus

1. 来源不丢失：近战外部动作、投射物、碎片和后续效果不能通过角色当前活动技能猜测归属。
2. 资源不重复：并发预留、失败退款、重复回调与场景解绑不能造成重复扣款或收益。
3. 行动不覆盖：绕过冷却不等于绕过当前动作；缓存只有一条，普通 AI 不抢占。
4. 评分不串轮：伤害间隔超时后，旧请求继续执行但不能重新开窗或进入新轮。
5. 暂停可恢复：终结限时 UI 与演出独立推进，成功、超时、异常和退出均释放接管。

## 阶段 1：伤害来源与专注基础

### 范围

- 统一伤害来源、实际伤害事件、请求/轮次/命中身份和专注收益属性。
- 数据沿现有命中、投射物和子技能上下文传播。
- 场景级专注池：积累、容量、预留、提交与退款。
- 重复费用记录与计算的纯数据接口；正式轮次时机留给阶段 3。
- 最小调试显示和独立基础预览。

### 不包含

1—4 输入、连携槽接入、动作缓存、冷却策略改动、伤害窗口、评分 UI、终结暂停、正式连携技能内容。

### 可观察成果

普通有效伤害能推动专注调试条；来源标为连携/终结的测试伤害正常扣血但不回充。预留量、已用量和实际可用量可以查看；无需新连携指令系统。

### 验收门槛

- [x] 伤害与治疗数值、仇恨、死亡、旧生命信号无回归。
- [x] 多目标、近战与碎片数据归属正确；一次结算不重复发布。
- [x] 资源并发、幂等和重复费用契约测试通过。
- [x] 缺少组件时旧场景正常运行；场景重绑与动态单位无泄漏。
- [x] Inspector、目录和预览由人类可直接查看与编辑。
- [x] 阶段 review 通过并交付变更清单，才进入阶段 2。

## 阶段 2：实时连携指令与 AI 行动接入

详细设计：[阶段二实时指令设计](../Specs/2026-10-13-burst-combo-stage-2-command-design.md)，用户已确认，并同意先复用现有技能作为连携测试内容。

详细计划：[阶段二实施计划](2026-10-13-burst-combo-stage-2-command-plan.md)，四组检查点、八项任务已实施；[验收记录](2026-10-13-burst-combo-stage-2-validation.md)与[配置指南](../../../SkillSystem/04-Docs/SquadChainCommandConfigurationGuide.md)记录实际交付。

### 范围

- 连携槽、1—4 InputMap 路由、专注预留与释放提交。
- 单伙伴一条缓存、最早合法行动机会、不覆盖已开始动作。
- 连携不检查技能和公共冷却，但保留存活、控制、目标与动作规则。
- 执行时读当前玩家锁定；目标失效沿用已有策略。
- 请求来源与阶段 1 费用接口接入，显示施放/待执行/不可用。
- 用独立测试技能实例复用现有表现，不改常规技能充当连携。

### 可观察成果

玩家能够直接调用伙伴。忙碌时有缓存反馈，完成动作后出手；不同伙伴独立执行，同一伙伴不叠加动作。

### 验收门槛

- [x] 冷却与动作占用分离，原 AI 策略保持可用。
- [x] 缓存满、死亡、无目标、接近失败与退出不重复扣费或丢失退款。
- [x] 目标在执行时解析，换锁定不覆盖已发出的攻击。
- [x] 测试批次验证重复计价；不引入临时游戏重置键或固定整轮时限。
- [x] 独立review问题均已修复并经RED→GREEN及全回归验证；仍须用户另行授权才进入阶段3。

## 阶段 3：伤害连携窗口、评分与完整反馈

### 范围

- 首笔有效伤害开窗，后续伤害刷新间隔；施放和治疗不续窗。
- 正式轮次、重复计数重置、旧记录清理、迟到伤害隔离。
- 综合评分与专注、伙伴入口、连击数、进度、间隔倒数 UI。
- 达分发出终结资格事件，暂不暂停或播放终结。

### 可观察成果

常规战斗积累专注 → 实时调用连携 → 看伤害反馈接续 → 间隔超时结算 → 下一轮，形成可实际验证的循环。

### 验收门槛

- [ ] 同帧与超时边界确定，不能旧轮关闭后又被旧伤害重开。
- [ ] 窗口关闭不取消已受理请求，不等待全部交付结束。
- [ ] 旧投射物、缓存和碎片不串轮，来源及收益属性不变。
- [ ] 同一真实命中不因多回调或元素拆分重复增加连击。
- [ ] UI 不计算业务，输入不穿透；实际体验 review 通过才进入阶段 4。

## 阶段 4：限时终结选择与独立演出

### 范围

- 达分后暂停、限时选择、灰显、全不可用跳过、超时放弃。
- 终结覆盖当前行为但保留未被中断的后续缓存，使用统一退款路径。
- 终结演出独立推进，普通模拟冻结；释放点主要效果结算一次并立即恢复。
- 暂停、镜头、动作接管的异常清理。
- 一个最小终结样例及独立预览；四职业完整终结内容另行设计。

### 验收门槛

- [ ] 所有资格限制和灰显反馈正确；旧输入不穿透为终结选择。
- [ ] 不等待被冻结的普通动作或普通物理投射物。
- [ ] 主要效果只交付一次，残留视觉不重复扣血。
- [ ] 超时、失效、场景切换与演出失败都恢复战斗。
- [ ] 全循环与既有战斗回归通过，完成最终 review。
