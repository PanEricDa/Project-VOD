# Caster 第二技能「炎爆术」设计

## 目标与边界

炎爆术用于兑现 Firebolt 铺设的灼烧：普通情况下仍能向指定敌人发射一枚单体投射物；当前战斗中存在其他灼烧敌人时，从 Caster 的发射点同时向他们各发射一枚。它不是命中后溅射、分裂或连锁技能。Archer 的爆裂箭仍可利用未被炎爆消耗的灼烧；两者对同一状态的竞争是预期的时机选择。

首轮仅实现一次齐射、单体命中伤害和灼烧消耗。不增加灼烧层数、周期伤害、目标数量上限或特殊连击规则；伤害量属于测试后可调整的技能数据。

## 确定的玩法规则

1. Caster 按现有技能规则选定一个合法的主要目标，进行 1.2 秒施法。炎爆冷却为 6 秒。
2. 在**实际释放节点、生成任何投射物之前**，一次性获取当前战斗中的所有存活敌人；以主要目标加上其中所有带 `burning` 的敌人形成去重目标快照。附加目标不受主要目标射程或额外人数上限约束。主要目标没有灼烧也保留；主要目标有灼烧也只占一枚。
3. 使用同一次技能释放和同一个 Caster 发射点，向快照内每个目标各创建一枚单体追踪投射物，并在同一释放阶段启动全部投射物。发射之后不再搜索目标；其他敌人之后获得灼烧不会追加投射物。
4. 每枚投射物独立飞行、独立命中、独立结算一次单体伤害，不产生范围伤害或子投射物。已指定的附加目标若在飞行中失去灼烧，投射物仍按既定目标飞行；失效、死亡或未命中目标不结算伤害。
5. 单枚投射物有效命中后，移除该受击目标当前的 `burning`（如有）；未命中不消耗。即使目标是施放时不带灼烧的主要目标，也只在命中时检查并移除当时存在的灼烧。一次齐射只产生一次技能冷却和角色动作；各投射物的命中结果分别记录。
6. AI 自动施放的软性条件是当前战斗中至少两名存活敌人带灼烧。显式指令跳过此软条件，仍可单体施放；基础合法性、冷却、目标选取与动作流程保持现状。AI 中满足条件的炎爆优先于 Firebolt，以免刚铺好的灼烧被下一轮 Firebolt 决策覆盖。

## 与现有框架的接合

- `Caster.tscn` 的第二常规技能槽装配独立的 `PyroblastSkill.tscn`；根节点继续使用 `SkillBase` 和现有远程模板，不增加炎爆专用 `SkillBase` 子类。
- 现有 `ArcProjectileDeliveryConfig/Session` 已能同帧发射多枚，但 `shot_count` 会把所有弹发向同一目标。需为交付层增加**可复用的目标列表策略**：默认策略仍为原单目标连射；状态筛选策略可在释放前取得“主要目标 + 符合状态的其他敌人”。交付会话须保存每枚投射物对应的目标，不以 `context.resolved_target` 判断全部命中。
- 目标来源是当前战斗的敌方单位集合，不从主目标附近查询，也不使用命中后的 `TriggerSkillEffect`。一次释放的目标快照只读，不改变其他技能的感知和目标选择。
- 炎爆使用通用伤害 Effect，并追加可复用的 `ConsumeNamedStatusSkillEffect`。`StatusEffectComponent` 增加通用的按 ID 移除命名状态接口，正确发送现有 `named_status_changed` 信号，使头顶状态圆点同步消失。状态 ID `burning` 仅在炎爆场景里配置，不写入通用效果代码。
- AI 的两目标灼烧门槛作为 `SkillConditionBase` 子节点，适用范围选 `AUTOMATIC_ONLY`。条件读取与释放目标快照使用同一“当前战斗中的敌方”口径，但分别在决策时与实际释放时求值；后者决定最终投射物数量。
- 冷却、资源、动作与打断仍由现有 `SkillBase`/`SkillHost` 管理。施法被打断时不生成投射物；释放后个别投射物未命中不取消其余分支。

## 首轮表现与平衡验证

投射物从 Caster 同一个发射点同时射出，以简单、可区分 Firebolt 的视觉表现为先；不要求额外连携动画。单枚基础伤害需高于 Firebolt，但具体基础值及攻击力倍率在实战测试中确定，不能把它们当作目标数量的隐性限制。

验证至少覆盖：零灼烧时仅主要目标一枚；主要目标灼烧但不重复；两个及多个其他灼烧目标同帧齐射；状态在施法期新增、在发射后新增、在飞行中消失；单枚未命中或目标死亡不影响其他命中；命中移除状态与 UI 同步；AI 两目标门槛和显式单体施放；Firebolt 范围铺灼烧、炎爆齐射、Archer 爆裂箭之间的真实战斗顺序。
