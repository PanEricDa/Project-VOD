# 角色技能槽设计

状态：对话方案已确认；书面规格待审阅。本文不代表已实现。

## 1. 目标与边界

为已有角色提供清晰的技能装备位置，支持后续扩充技能和爆发连击验证。保留现有 SkillHost、SkillBase、技能场景及动作执行流程。

本期只实现编辑器装配、运行时读取、配置校验、AI 候选范围调整和现有角色迁移。不实现爆发编排、专注消耗、评分、终结技内容、技能背包、解锁、战斗中换装。普攻、移动、闪避仍是行动，不进入技能槽。

## 2. 当前基线与方案选择

`SkillSystem/01-Core/SkillHostComponent.gd` 自动注册固定 SkillSocket 下的直接 SkillBase 子节点。当前自动选技遍历注册列表，按 automatic_cast_enabled、冷却、目标及 Condition 过滤，再选择最高 ai_priority。

采用已确认方案：在 SkillHost 增加槽位引用，继续手工挂载技能场景。暂不采用 PackedScene 数组自动实例化，也不增加 SkillSlot 子节点或独立槽位 Resource。

原因：保留技能节点上的角色级参数覆盖及现有路径，避免新增生命周期管理。尤其保留 Priest 对 HolyLight Delivery 的现有覆盖及所有用户已调参数。

## 3. 策划配置

SkillHost 的 Inspector 新增 Skill Slots 分组，仅增加两个字段：

| 字段 | 类型与默认值 | 含义 |
| --- | --- | --- |
| regular_skills | Array[SkillBase]，默认两个 null | 常规技能槽；数组位置稳定，允许空槽及扩展长度 |
| finisher_skill | SkillBase，默认 null | 终结技槽；不参与普通 AI 选技 |

操作：将技能 .tscn 实例化到 SkillSocket，再将节点拖入槽位。技能自身的条件、冷却、效果及表现仍在技能节点配置，不在槽位重复配置。

同一角色常规与爆发使用同一技能实例；未来连击中重复选取同一槽位不复制实例，也不占用另一个装备槽。

## 4. 注册、装备与请求边界

- 注册表示 Host 管理该技能的拥有者及动作信号；保留现有自动发现与注册接口。
- 装备表示技能被有效槽位引用。空槽不自动补齐，未装槽的节点不能参与普通 AI 选择。
- 普通 AI 只从有效常规槽中取候选，继续执行既有自动施放开关、优先级及合法性判断。
- AI 的站位参考范围也仅依据有效常规技能，并保留现有“不因技能冷却改变战术站位”的规则。终结技及未装备技能不得影响常规站位。
- 现有 request_skill 显式入口限定到有效常规装备，避免绕过装备边界使用未装槽技能或终结技。继续保留原有参数和施放合法性逻辑。
- 提供 request_finisher 单独入口，读取有效终结技并走相同底层施放链路，不新增评分判定。本期仅提供入口，未来连击系统负责达标后调用。
- request_finisher 不受技能 automatic_cast_enabled 开关影响，但仍遵守显式请求的原有 Condition 作用域、目标、冷却、动作占用及施放禁用规则。本期不实现爆发冷却豁免。
- get_registered_skills 仍返回注册列表副本，不改成装备列表，避免混淆调试与装备语义。

## 5. 读取接口与槽位语义

Host 提供以下能力，具体请求参数沿用既有请求上下文约定：

- get_regular_skill(slot_index: int) -> SkillBase：索引从 0 开始；越界、空槽或无效配置返回 null，不压缩槽位。
- get_equipped_regular_skills() -> Array[SkillBase]：按槽位顺序返回有效常规技能的列表副本，供 AI 使用；列表位置不可当作原始槽号。
- get_finisher_skill() -> SkillBase：返回有效终结技，缺失或无效返回 null。
- request_finisher：显式请求终结技，失败返回 false，不跳过底层合法性检查。

不提供运行时换装接口。不引入新的槽位变化信号、装备管理器或技能数据资源。未来编排界面根据原始槽位索引读取技能；确认序列后固定技能实例引用，不在执行中反复根据槽位重选。

## 6. 校验与错误处理

有效槽位必须引用本 Host 的 SkillSocket 直接子节点，且运行时已成功注册。技能 ID 继续在同一个 Host 内唯一。

确定性处理规则：

1. null 是合法空槽，无错误提示。
2. 引用其他角色、其他父节点、已释放节点或未注册技能时，该槽运行时无效。
3. 常规槽重复引用同一实例时，仅第一个位置有效，后续位置无效并给出配置警告。
4. 常规与终结技引用同一实例时，保留有效常规槽，终结技槽无效并警告，避免该技能兼任两种装备身份。
5. 重复 skill_id 仍由注册逻辑拒绝；拒绝注册的实例不能成为有效装备。
6. 注销或释放技能后读取槽位不得返回失效对象，不因空缺自动换用其他技能。
7. 编辑器校验依据场景父子关系与 ID，不依赖仅在运行时建立的注册列表。字段修改后刷新配置警告；运行时读取还需检查注册有效性。

无效请求返回 false，不造成施放、费用扣除或冷却变化。增加的参数、公开方法及其参数必须在声明附近提供简体中文说明。

## 7. 现有角色迁移

| 角色 | 常规槽 0 | 常规槽 1 | 终结技 |
| --- | --- | --- | --- |
| Guardian | GuardianShieldSkill | GuardianTauntSkill | 空 |
| Priest | HolyLightSkill | GreaterHealSkill | 空 |
| Caster | FireboltSkill | 空 | 空 |
| Archer | 空 | 空 | 空 |
| Saber | 空 | 空 | 空 |

修改单位源场景的 Host 槽位配置，不删除或重新实例化现有技能节点，不改变技能数值、AI 优先级、Condition、特效或动作参数。

不修改 `Scenes/TestScene.tscn` 中的任何单位实例。不在本期给玩家新增 SkillHost 或技能。执行前检索全部非归档 Host 使用者及测试夹具；需要选技或显式请求的夹具必须显式装槽，不以旧的“注册即装备”行为兜底。

## 8. 验收标准

- 基础 Host 默认两空常规槽、一空终结技；数组扩展后仍正常工作。
- 空槽保留原索引，查询越界安全；装备列表不泄露可修改的内部数组。
- 高优先级的未装备技能、终结技均不能抢占普通 AI；常规技能仍按现有优先级选择。
- 终结技即使开启 automatic_cast_enabled 也不能进入普通候选，但可以通过独立显式入口请求。
- 显式普通请求不能使用未装备技能或终结技；失败不产生施放副作用。
- 已装备技能原有条件、冷却、随机犹豫、动作路由和站位范围行为保持不变。
- 重复引用、跨角色引用、重复 ID、注销与释放引用的处理符合第 6 节。
- 实例化两个相同角色时，各自槽位引用自己的技能实例，不共享冷却；保存并重新加载角色场景后引用正确。
- Guardian、Priest、Caster 的已装备列表与迁移表一致，所有原有技能参数覆盖仍保留。
- 更新并运行技能 Host、角色装配、条件和重复施放等受影响回归测试；通过 Godot 实际加载验证场景和类型，不仅检查文本。
