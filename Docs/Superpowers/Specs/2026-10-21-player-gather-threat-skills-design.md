## 1. 目标与范围

为玩家装配两个独立常规技能：Q将附近敌人聚到身前，E对附近敌人施加限时大量仇恨。沿用SkillBase、SkillHost、Delivery、Effects、StatusEffect和敌人原有仇恨选敌；不建立玩家专属执行体系、仇恨权级或聚怪状态。

移动、普通攻击等原有行动不归入技能内容。玩家输入和角色动作只是SkillBase的请求端与执行适配端。

本轮不设计自由地板瞄准、技能获取/职业装配限制、战中换装玩法或新成长/资源体系。聚拢、临时挑衅首版均无伤害，不消耗队伍专注，不计连携评分。

## 2. 两个技能的初始参数

这些值为技能内容基线，不是成长/平衡结论；后续按Inspector调校，无需修改脚本。2026-10-21用户为方便验证，要求独立测试场景中的Q/E冷却均覆盖为2秒；下表10/12秒保留为正式内容基线，第二阶段沿用测试2秒覆盖。

| 配置 | Q：Gather | E：ThreatMark |
|---|---|---|
| InputMap | player_skill_1，Q | player_skill_2，E |
| 启动目标 | Self，无须锁定 | Self，无须锁定 |
| Delivery | InstantTarget / Caster Radius / World Scope | 同左 |
| 受影响关系 | Hostile | Hostile |
| Effect Radius | 3.5米（圆心沿释放朝向前移3米，用户当前配置） | 5米 |
| Base Cast Time | 0.2秒 | 0.15秒 |
| Skill Cooldown | 10秒 | 12秒 |
| 移动/转向 | 允许施法中移动和转向 | 同左 |
| 特有参数 | 身前1.5米、聚集区半径0.6米、位移0.12秒（用户当前配置） | 基础临时贡献2000点、持续8秒 |
| 选敌变化 | 不直接修改敌人锁定 | 依原有仇恨比较产生变化 |
| 结束 | 位移交回正常AI | 只撤销这笔临时贡献 |

启动目标Self与Delivery关系Hostile是不同层次。cast_range不重复承担当作范围半径；实际受影响范围半径唯一来自Delivery.effect_radius；圆心由Delivery.center_forward_offset_m配置，默认0不影响其他技能，拉拽当前设为3米。使用实际释放位置和稳定朝向快照；该圆心不是拉拽落点，落点仍为身前1.5米的0.6米圆盘。技能根节点关闭automatic_cast_enabled。

Q在释放瞬间冻结本次中心与稳定水平朝向；落点区域不持续追随移动中的玩家。拉拽期间临时忽略单位身体碰撞，允许在同一中心附近重叠；墙体、地面与重力保持。到达、取消、死亡或离树时恢复碰撞，再交回原有AI/物理移动散开，不新增散开系统，也不结束后补瞬移。

E不强制写入locked_target，也不承诺无条件盖过一切仇恨。普通Guardian嘲讽目前为400点普通仇恨，Duration=0保持原行为；玩家用足够大的临时数值维持当前MVP拉怪可靠性。到期后Guardian是否接管仍由正常仇恨结果决定。

## 3. 现有基础与扩展边界

- UnitBase已挂SkillHost，PlayerBase/Hero继承它；已有两个Regular Skills槽、注册/注销、显式请求、冷却和动作确认/释放/完成接口。
- 玩家AttackController尚无完整外部技能动作协议，输入也未接Q/E；不能只挂两个技能就认为链路完成。
- InstantTargetDeliveryConfig已经支持Caster Radius和World Scope，可以在释放时从当前世界收集敌方，不要求以玩家锁定组件充当范围搜索器。
- ThreatChangeSkillEffect当前只向普通池添加固定仇恨，不能在到期时安全撤回单独贡献。
- SkillMotionComponent用于施法者随动画移动，不作为拉动敌人的实现。
- StatusEffectComponent已有命名状态/属性修正，但命名状态尚不承载带来源的撤销绑定。
- 当前瞬发交付对apply=false使用fail-fast。可预期的不适用目标应在Effect适用性检查跳过，不伪装成内部执行错误。
- 未来手动地点/方向瞄准需要另行适配；现有SkillBase释放时会重写target_position，本轮不据此宣称已支持自由瞄准。

## 4. 装配与数据流

```text
PlayerSkillsTest / 后续正式Hero
  Hero
    SkillHost（已有）
      SkillSocket
        GatherSkill（SkillBase + PullTargetSkillEffect）
        ThreatMarkSkill（SkillBase + ThreatChangeSkillEffect）
    PlayerSkillInputComponent
    PlayerSkillController
    AttackController（已有，补外部动作协议）
  HUD
    PlayerSkillBar（可拆）
```

输入只发槽号；控制器读取槽位并请求Host；Host/SkillBase执行已有合法性和费用/冷却；动作执行器回传release_action、finish_action；Delivery收集目标；Effects执行业务。UI只读槽位及执行结果，不负责技能生效。

公开脚本接口应有中文说明；输入、HUD、技能都不通过具体技能ID相互识别，按键只认识槽号。本轮通过Inspector静态装配两个技能；动态换槽、装备事务和其他输入设备只保留后续接入边界，不要求现阶段实现或验证。

同一AnimationPlayer只由当前动作所有者管理。第一版忙碌请求明确拒绝并反馈，不建立隐藏长队列，不改变已有行动的抢占策略；具体外部动作细节在阶段一计划中与当前控制器逐项对齐。

## 5. 通用聚拢与物理执行

以下保留阶段二验证版历史；阶段五最终实现见5.1节，旧组件已移除。

PullTargetSkillEffect只计算目标请求，不直接改变CharacterBody3D的位置。ForcedMovementComponent保存本次目标、进度、来源弱引用与请求身份；AIUnitBase现有物理循环消费它，只保留一个最终move_and_slide。

强制位移生效期间不让导航移动同时覆盖本帧水平速度；结束后继续正常AI，不留下清除不掉的移动锁。

2026-10-21用户更新聚拢规则：Pull请求传入ignore_unit_collisions=true，仅临时添加对其他UnitBase身体的碰撞例外，允许重叠聚拢。通用位移接口默认false，保持其他调用原有碰撞行为。世界墙地、collision_layer/mask和技能命中Area不关闭；只恢复本请求新增的例外，不删除其他系统原有例外。忽略对象中途生成/删除/离树也要正确登记和清理；碰撞恢复先于终态通知，避免旧回调影响新请求。不把拉拽默认等同于打断、改仇恨或固定目标。

多次请求用身份隔离：后接受的一次替换旧位移，旧取消通知不能终止新请求。撞墙提前结束且不追补；来源死亡/离树、目标死亡和场景退出要正常清理。目标原地或已经处于聚拢区是合法无须移动结果。将来技能装卸不应改变已提交效果的归属，但运行时卸载/重装专项不属于当前验收。

Effect适用性默认兼容旧效果：缺少位移接收能力的单位只跳过拉拽，不能让整群后续目标都失效；如同一技能另有伤害Effect，其他适用效果仍能执行。零个实际效果应用不虚报受影响单位。

### 5.1 最终统一优化决定：被动位移内置UnitBase

2026-10-21用户确认方向；2026-10-22阶段五已实施。以下为原决定记录，最终入口为UnitBase.request_forced_movement及forced_movement_started/finished，Inspector只有forced_movement_enabled一个开关。关闭立即结束、恢复新增例外，重开不续旧请求。旧组件及装配已移除。

- 被动位移是玩家、友方和敌方共用的单位基础能力，应将通用请求接口、运行时状态与生命周期管理统一内置UnitBase，不再要求策划额外挂载ForcedMovementComponent节点。
- UnitBase在Inspector提供“允许被动位移”开关，默认开启；关闭时拒绝新的外力位移请求。参数须有中文说明，关闭时活动请求如何收束在实施时明确。
- PlayerBase与AIUnitBase仍在各自已有物理循环消费被动位移，保留重力、碰撞和一次最终move_and_slide；不把外力改为普通AI寻路命令，也不在UnitBase另起第二套物理移动。
- 技能Effect调用单位通用接口，不再依赖接收器子节点是否存在。当前独立组件仅为阶段二验证版实现，迁移时统一清理局部挂载、引用、文档和测试，不长期保留两套入口。
- 此决定取代“最终给EnemyBase统一挂接收器组件”的装配方向；没有必须外挂或不能内置的技术限制。本项已按阶段五确认计划完成，不借此提前推进其他功能。

## 6. 限时仇恨与Debuff生命周期

ThreatChangeSkillEffect增加duration_seconds，默认0兼容Guardian，正值创建临时贡献。正常值与临时贡献分开存储：

```text
get_threat_for(source) = 原普通仇恨 + 该来源所有仍有效临时贡献的当前值
```

临时贡献单独沿既有衰减曲线衰减。到期删除其剩余值，绝不简单“加2000、以后从总池减2000”，不恢复一张旧仇恨快照。所有查询/比例/选敌/事件/调试显示读取相同合计口径。

StatusEffectComponent是持续时间的唯一管理方，新增带来源与效果标识的状态记录及到期撤销绑定；ThreatComponent不再保存另一份8秒倒计时。命名状态temporary_threat可被已有状态查询与血条展示读取。

身份按目标、施加者、效果标识区分。同来源同效果刷新，不叠加；不同来源各自到期。来源标识不依赖已卸下的Effect节点，撤销句柄不得持有已销毁技能或场景的强引用。创建失败应回退自身新写入，不破坏旧有效记录。

到期、驱散、来源死亡/离树、敌人死亡或归位清表，均需同步解除状态与贡献；重复撤销无害；移除旧状态不能删新贡献。Guardian普通仇恨、普通伤害和治疗仇恨的行为不变。

## 7. 接口兼容与当前实现边界

- 本轮以Inspector静态装配两个技能为准，复用Host已有槽位、注册/注销入口与通知；不新增原子装备、热换槽或完整装卸事务。
- 保留槽号请求、受理/拒绝、动作开始/释放/结束/取消等接口和信号；输入、HUD和具体技能不写死相互依赖。
- 技能场景内容在SkillSocket显式可见；不依赖隐藏运行时装配来解释当前技能。
- PlayerSkillBar放在独立HUD，通过绑定接口读取Host，不成为技能能否释放的前置条件。
- 正常施法取消、死亡与场景退出仍须解除动作/移动占用、断开自身连接并清理临时状态。这是技能正常运作所需的基础安全，不等于动态装卸系统。
- 范围和关键数值都只有一个来源。动作、施法视觉、释放视觉、音频、镜头走技能根节点资产接口；无表现资产不影响Gameplay。
- 所有正式外部资源由Godot正式保存、验证UID，强类型资源需可Quick Load。
- 延后：运行中换技能、反复删除/重建输入或HUD、装卸回滚、跨装备冷却继承、热插拔组合和专项压力测试。未来具体系统设计后再落实相关行为与验收，不为当前预留能力提前建配套子系统。
