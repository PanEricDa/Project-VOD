# 技能成功释放表现：视觉、音效与镜头资源接口设计

> 日期：2026-10-14。
> 状态：用户确认设计/计划后已实施；自动化验证完成，实际听感待用户确认。详见[实施计划](../Plans/2026-10-14-skill-release-presentation-plan.md)及[验收记录](../Plans/2026-10-14-skill-release-presentation-validation.md)。
> 目标：技能成功施放的一瞬间统一触发视觉、音效和镜头表现请求；策划在技能根节点 Inspector 中直接选择资产，留空即不播放。
> 范围：底层接口和通用播放链路，不制作特定技能表现，不进入爆发连携阶段三、四。

## 1. 设计结论与约束

复用 SkillBase 已有 Presentation 配置和 DeliveryRunner 接受边界。新增释放音频、镜头资源两个字段；在已有 RuntimeEffects 子节点挂载通用播放脚本，不增加技能场景层级，不要求每个技能手工连线。

本次不把表现当作 SkillEffectBase 数值效果，不增加独立技能管线、表现资产组合资源、全局 Autoload 或技能专用脚本。技能负责成功时点，播放组件负责表现，资产负责自身美术与播放内容。

策划只需要打开具体技能场景并配置根节点。普通、连携和内部触发技能共用这套机制；是否播放由该技能实例的资产配置决定，不按职业、请求来源或 Trig_ 文件夹增加隐含规则。

所有 export、公开信号、公开方法及跨模块输入均须附紧邻的简体中文说明，注明默认行为、单位、生命周期和影响范围。内部参数不重复暴露到 Inspector。

## 2. 已有实现与需要纠正的时点

### 2.1 已有配置

`SkillSystem/01-Core/SkillBase.gd` 已有：

- cast_effect_scene：动作确认开始时生成的施法/蓄力视觉。
- release_effect_scene：释放视觉 PackedScene。
- release_effect_anchor：释放位置/附着方式，已有四种 PresentationAnchor。
- cancel_effect_scene：释放前取消时的视觉。

`SkillSystem/01-Core/SkillBase.tscn` 已有根节点、DeliveryRunner、RuntimeEffects。远程和近战模板继承此基础场景。

### 2.2 当前时序问题

目前 `_commit_release()` 在 Runner.execute 前调用 `_spawn_release_presentation()`。此时后续指令授权、交付配置或投射物启动仍可能拒绝交付，因此已有视觉不能严格表示“成功施放”。

本次移除该位置的成功释放视觉调用，统一在 `_on_runner_delivery_started(context)` 的接受边界触发。原有蓄力结束及 release_started 通知保持既有职责，不把 release_started 重新解释成已接受或已命中。

依据：[阶段二设计：费用与真实释放边界](2026-10-13-burst-combo-stage-2-command-design.md#10-费用与真实释放边界)。

## 3. 成功施放的定义与触发次数

成功施放是“交付已经被接受”，不是所有效果最终成功或最终命中。

```text
activate
  ├─ CHARACTER_ACTION → 动作开始/施法时间 → 动画释放帧
  └─ DIRECT_TRIGGER → 直接释放
                     ↓
             释放检查、授权、费用、交付启动
                ├─ 未接受 → 不播放成功释放表现
                └─ 接受通知 delivery_started
                         ↓
                  标记本次已释放
                  保持 Host/专注提交通知顺序
                         ↓
                  通用释放表现（恰好一次）
                    ├─ 视觉资产
                    ├─ 音频资产
                    └─ 镜头资源请求
                         ↓
             既有瞬发效果／投射物／区域执行与最终结算
```

投射物接受通知发生在有效发射启动后；表现和发射处于同一次释放调用，不人为多等待一帧。瞬发效果继续在接受通知完成后执行。不得把表现移动到最终命中回调，或等 execute 返回后再统一播放，从而让同步治疗/伤害先于释放表现。

| 情况 | 成功释放表现 |
|---|---|
| 请求受理、等待接近、正在施法 | 不播放；蓄力视觉仍由原有 Cast 接口负责 |
| 施法时间完成且交付接受 | 同一释放调用内播放一次 |
| 瞬发或直接触发且交付接受 | 立即播放一次 |
| 打断、沉默等既有规则阻止释放 | 不播放 |
| 目标/费用/授权/配置检查拒绝，或投射物 launch 未接受 | 不播放 |
| 投射物已经发出，之后目标死亡、未命中或效果失败 | 保留已发生的释放表现，不退款或回滚表现 |
| 连射、多目标齐射、多目标瞬发 | 本次技能施放只播放一次，不按弹数/目标数/命中数播放 |
| 内部触发子技能 | 每个成功触发的技能实例按自己的配置播放；默认空资源 |
| 重复施放同一技能 | 每次新释放各播放一次，允许独立重叠 |

复用 `_release_accepted` 和当前 context 身份检查，不新建全局去重池。旧会话的最终结果不能触发新一轮释放表现。

## 4. Inspector 配置契约

保留字段名称，避免现有场景资产引用丢失。只整理 Presentation 下的 Cast、Release、Cancel 分组。

```text
技能根节点 / Inspector
  Presentation
    Cast
      Cast Effect Scene
    Release
      Release Effect Scene
      Release Effect Anchor
      Release Audio Stream
      Release Camera Effect
    Cancel
      Cancel Effect Scene
```

| 字段 | 类型 | 默认 | 职责与约束 |
|---|---|---|---|
| release_effect_scene | PackedScene，已有 | null | 选择释放视觉 .tscn；根为 Node3D，只承担表现 |
| release_effect_anchor | PresentationAnchor，已有 | ACTION_ORIGIN | 决定视觉位置/附着和音效、镜头请求的位置快照 |
| release_audio_stream | AudioStream，新增 | null | 直接选择导入音频或兼容 AudioStream 资源；用于一次性释放声音 |
| release_camera_effect | CameraEffectProfile，新增 | null | 只接受镜头配置基类/子类；本期发出请求，不执行镜头移动 |

根节点实际新增两个 export。每个通道独立可空，不增加总开关、播放器 NodePath、每技能音量/随机音调、表现延迟、镜头优先级或额外颜色参数。

单独的 GPUParticles3D/CPUParticles3D 是节点，不是此槽位接收的 PackedScene 资产。需要把粒子或粒子组合保存为独立 .tscn，再拖入 Release Effect Scene；不误将材质、纹理当作特效场景。

修改既有技能名称提示逻辑不在本次范围。技能类型字段也不参与表现资产推断，伤害/治疗等类型不会自动替策划选择特效。

## 5. 组件职责与装配

### 5.1 SkillBase

负责检查当前接受通知、恰好一次播放入口、读取四项 Release 配置，以及对外提供镜头请求信号。不负责音频播放计时，也不直接读写 Camera3D。

在进入 Runner.execute 前保存本次发射变换与接受后播放所需数据。接受回调内先调用播放器的 prepare_release 取得资产、释放位置和附着意图快照；此准备步骤只读取，不实例化、不播放、不发镜头请求。然后保持现有 delivery_started → Host.skill_released → 专注提交的顺序，再调用 play_release 执行表现通道。

表现使用这次回调的数据，不在信号发出后再次依赖 `_current_context` 或正在执行的技能状态。同步回调可能使目标失效、改变场景或结束技能实例，调用前必须重新检查世界和组件是否仍有效。

保留既有冷却、AI 犹豫、条件、费用和目标规则。只移动成功视觉的时点，不改交付接受或费用提交的业务语义。

### 5.2 SkillReleasePresentationPlayer

位置：`SkillSystem/01-Core/SkillReleasePresentationPlayer.gd`。

继承 Node，挂在基础场景已有 RuntimeEffects 节点。没有供策划重复填写的 export，子节点名称和固定装配由模板管理。

公开入口分为两个步骤：prepare_release 接收本次 context/发射变换及根节点选定的视觉、锚点、音频和镜头资源，返回本次临时快照；play_release 只接收该快照，不重新解析锚点或读取当前技能。快照使用内部数据结构，不新增供策划配置的 Resource 类型或文件，不保存整个 SkillContext/command_request，也不作为播放器的跨次共享状态。

组件负责解析锚点、实例化视觉、创建声音播放器及同步转发镜头请求。视觉位置辅助逻辑从现有 Release 方法迁移并保持行为；Cast/Cancel 路径不顺带整体重构。

未来对外订阅仍从 SkillBase 根节点进入，避免策划或其他系统需要知道 RuntimeEffects 的内部脚本、节点路径。

### 5.3 不增加 gameplay Effect

SkillEffectBase.apply 是目标效果结算接口。成功释放表现发生在结算之前，且每次施放一次；放进 Effects 会随每个目标执行，导致声音和镜头重复。因此不新增“释放特效 Effect”，不改 Delivery 资源配置方式。

## 6. 锚点与定位

| 锚点 | 视觉 | 音频与镜头请求 |
|---|---|---|
| ACTION_ORIGIN | 本次动作发射变换；一次性世界表现 | 发射点的世界位置/变换快照 |
| CASTER_FEET | 附着施法者脚底；保留去除俯仰/侧倾的水平目标朝向 | 释放时脚底世界位置及水平变换 |
| RESOLVED_TARGET | 附着已解析目标，局部单位 Basis；不继承武器倾斜 | 释放时目标世界位置及对应变换 |
| TARGET_POSITION | 本次目标位置；一次性世界落点，单位 Basis | 同一个世界落点快照 |

各通道共用一次锚点解析，不各自重新选择目标。对目标/施法者使用有效性检查；无法继续附着但已有合法快照时，可在合法世界父节点播放一次性世界视觉。没有合法快照或世界已经退出时跳过，不补选战斗目标。

先正确定位，再启动视觉播放，避免 ready/自动播放阶段在世界原点出现一帧。不得重复调用资产的自动播放和 play 导致双重启动；沿用已有资产协议，支持旧资产而不要求统一重写。

## 7. 视觉生命周期

视觉资产根节点为 Node3D；常规资产是一段一次性播放，自行结束并释放实例。兼容现有自动播放、effect_finished/auto_free_on_finished 等资产行为，不强制新视觉基类。

核心规则：成功释放的视觉不作为技能动作或技能实例的子生命周期。世界视觉挂到本次合法 delivery_parent，附着视觉挂到对应单位；不挂在技能节点下。

- 技能进入冷却/空闲、卸载或短生命周期触发实例结束，不提前清除已接受的释放视觉。
- 附着单位销毁时，该视觉自然随父节点清理。
- 世界卸载时，世界视觉自然清理，不存入 Autoload。
- 普通取消只影响尚未成功释放的 Cast/Cancel 表现，不撤回已经播放的 Release。
- 旧 `_runtime_effect_instances` 不再承担 Release 实例的退出销毁；保持 Cast/Cancel 的既有清理，不把三类实例混为同一生命周期。
- 完成回调及回收保护绑定到表现实例自身，不能依赖已经销毁的 SkillBase/播放组件才能回收。
- 不跨实例修改共享场景子资源、材质或动画；保留既有资产的实例隔离方式。

无法正确自行结束的误配置场景需要配置警告与回收保护。通用播放器给释放视觉提供内部 30 秒看门狗，随游戏暂停/时间缩放计时，只作异常驻留兜底，不承担正常美术时间轴；不暴露该参数，不用它替代资产结束。本期 Release 视觉资产应为短于该上限的一次性表现。长期光环不属于本次一次性释放视觉，应走状态/持续表现接口。

## 8. 音频播放契约

底层按需创建 AudioStreamPlayer3D，位置来自同一个锚点快照，默认全向播放。无需在技能或角色源场景配置 AudioStreamPlayer 节点。

声音挂到世界父节点，不跟随动作槽或技能实例；以释放时位置发声，不持续跟随目标移动。每次释放独立声音实例，连续释放允许重叠。正常 finished 直接释放播放器，不经已结束技能的回调清理。

统一总线优先 SFX；未建立 SFX 总线时回退 Master。不为本功能修改 project.godot/总线布局，不将音频距离或衰减变成每技能参数。

释放声音为一次性资产。对可识别的循环配置给出警告并跳过该声音通道，不临时修改共享 AudioStream 的循环属性。无法获得结束时长的流使用内部 30 秒回收保护；能获得有限时长时保护期限为该时长加内部 1 秒结束余量，不截断合法较长音频。

暂停由播放器的场景处理模式处理；不自行调整 Engine.time_scale，也不自动对音频做变速/拉伸。正式听感验证要确认实际发声、位置与重叠，不能只靠节点存在认定声音正常。

## 9. 镜头资源与预留出口

新增 `Effects/Camera/CameraEffectProfile.gd`，继承 Resource，提供可被 Inspector 识别的强类型。基类本期不暴露震动、FOV、位移或持续时间参数，不保存运行状态，不执行镜头查找或移动。

根节点新增公开信号 `camera_effect_requested`，参数约定：

| 参数 | 类型/含义 | 约束 |
|---|---|---|
| profile | CameraEffectProfile | 本次选择的非空配置；消费者只读，不能把状态写回共享资源 |
| source | Node3D | 施法者；发送前已失效则为空，消费者也须允许引用随后失效，不用它确定技能成功与否 |
| target | Node3D | 本次已解析目标，可为空/随后失效；不让镜头接口重新选择技能目标 |
| world_transform | Transform3D | 已解析的有限世界变换快照；对象失效后仍可用的位置依据 |

RuntimeEffects 在对应接受回调中发出请求，由 SkillBase 同步对外转发。资源为 null 时不发请求；无人订阅时正常忽略，无错误、无等待、无镜头动作。

本期“镜头链路完成”的验收范围是：强类型槽位 → 本次成功释放 → 完整请求信号。并不声称已有镜头执行器。未来镜头侧可通过既有 SkillHost 技能注册/卸载入口订阅 SkillBase 信号，并解释具体 CameraEffectProfile 子类。

本期不改 CameraFollowController、HitFeedbackBridge，不新增 CameraRig 节点或镜头仲裁。未来镜头执行器必须与跟随、分档缩放及命中震动协调，但这是独立设计/实施，不由技能直接写相机位置。

## 10. 失败隔离与开销

各通道独立执行：空视觉不影响声音，声音不能播放不影响视觉，镜头无人订阅不影响另外两项。配置错误可给编辑器警告/运行时诊断，但不得撤销已接受的技能、退还费用、改冷却、阻断命中或把表现完成当作动作结束。

基础模板 RuntimeEffects 装配错误需明确警告；技能 gameplay 仍按原规则执行，不因缺少表现播放器崩溃。不增加通道失败回退为另一个技能等规则。

全部资源为空时不实例化视觉或声音，不创建计时器，不广播空镜头请求。每个已装备技能只有模板已有 RuntimeEffects 节点；真实释放才产生所配置的一次性实例。本期不实现对象池、全局播放队列或复杂并发上限。

## 12. 独立预览的范围

预览场景提供明确的资产选择入口、位置锚点和一次播放 UI 按钮；允许使用已有一次性视觉，不要求制作新内容。预览参数只服务于工具，不复制成正式技能的第二套配置入口；不硬编码快捷键，也不为预览改项目 InputMap。说明它验证的是表现播放及镜头请求，不是技能费用、AI 行动、伤害或命中。

为本期没有具体资产的通道提供可观察检查：测试用短音频可在内存生成；镜头请求计数和位置显示可用内存 CameraEffectProfile。不得把这类测试占位物自动保存或装备到正式角色。

回收和重复播放在预览自身展示，但技能成功/失败时点必须由独立测试驱动真实 SkillBase 与 Runner 验证，不能只手动发一个成功信号就宣布完整链路通过。

## 13. 实施验收标准

后续实施必须按测试先失败、最小实现、测试通过的方式推进；本文记录待验证契约，不宣称实现或测试已经完成。

1. Inspector 根节点只增加 AudioStream 和 CameraEffectProfile 两项；既有视觉/锚点配置保留，所有字段有中文说明。
2. 蓄力、排队和请求受理不产生 Release；真实施法完成并接受后，各非空通道恰好一次。
3. 释放前目标失效、取消、费用/授权拒绝、交付启动未接受均不产生成功表现。
4. 瞬发交付顺序为既有接受/费用通知 → Release 表现 → 效果结算；接受后效果失败不撤回表现。
5. 投射物与多目标/连射均每次施放一次；同步 launch 命中、延迟命中及旧会话回调不重复触发。
6. 普通、CHAIN 和 DIRECT_TRIGGER 共用入口；不通过用途标记隐藏禁止通道。
7. 四种锚点保持世界/附着坐标与水平朝向；目标移动、失效以及同步回调改变 context 后仍使用本次正确快照。
8. 子技能实例成功后立即结束、重复施放和动作结束均不截断 Release；声音/视觉自然结束、单位销毁、世界卸载正确回收。
9. 两个技能同时播放不串上下文/资源；无失效 Callable、重复监听、长期强引用或节点数量持续增长。
10. 空资源、错误视觉根类型、循环音频、无镜头订阅分别独立处理，不改变 gameplay 结果；内部回收保护可测。
11. 镜头强类型槽可创建/选择兼容类型、请求参数完整；无实际相机移动。若测试创建外部资源，正式保存、UID/类型验证和清理也属于验收。
12. 检查已有视觉场景、模板继承、费用事务和全部活跃测试；以实施时完整枚举为准，不用旧测试数量代替实际运行。
13. 实际运行独立 Preview，验证视觉与可听声音，观察镜头请求及重复播放回收；不自动修改 TestScene/TestCombatRoom 单位或正式技能资产配置。
