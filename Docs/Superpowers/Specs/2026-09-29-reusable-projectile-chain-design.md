# 可复用投射物连锁效果设计

状态：详细设计，待用户审阅。本文不授权实现；数值为首轮验证配置，不代表最终平衡。

## 1. 目标与边界

以弓手的「爆裂箭矢」为首个使用者，为现有技能与投射物体系补齐可组合的命中后效果。主箭命中并造成正数实际伤害后，向附近最多三个敌人发射低伤害碎片；每枚碎片命中并造成正数实际伤害时，若受击者在扣血前已有「灼烧」，再对其附近最多三个敌人造成一次较低的直接伤害。追加伤害不再产生碎片或再次触发追加伤害。

技能负责何时施放、选择首个目标、冷却和 AI 优先级；投射物只负责飞行和报告命中；技能效果负责伤害、筛选和后续生成。该链在普通 AI 施放和未来爆发编排中使用同一套效果，不设爆发专用命中算法。普攻、移动和闪避不并入技能系统；不修改 `Scenes/TestScene.tscn` 中任何单位实例。本期不实现连击编排、终结评分或新的物理弹道类型。

## 2. 已有基线与取舍

| 现有内容 | 已有职责 | 本设计中的处理 |
| --- | --- | --- |
| `Item/Projectiles/TrackingArcProjectile.gd`、`Arrow.tscn` | 目标抵达式抛物线、两参数 `launch(target, start_position)`、`projectile_hit`；不结算伤害 | 保留脚本和普攻契约。主箭、碎片可使用同一脚本的不同视觉场景 |
| `AIRangedCombatSystem.gd` | 弓普攻创建 Arrow、接收命中，再由战斗系统结算伤害 | 不让技能经此普攻入口绕行；只复用“投射物报告命中，调用方结算”的分工 |
| `FireballProjectile.gd` | 火球追踪、物理碰撞、爆炸范围候选收集 | 保留火球行为；仅提取或借鉴通用附近目标筛选，不把它变成弓箭父类 |
| `TrackingProjectileDeliveryConfig.gd`、`SkillDeliveryRunner.gd` | 火球式八参数发射与单次在途交付 | 保持旧契约兼容；为 Arrow 式两参数发射新增交付适配及独立运行会话 |
| `SkillBase.gd`、`SkillEffectBase.gd` | Skill 场景直接子效果按顺序应用；效果当前返回布尔成功 | 保留节点组合方式；提供每目标命中结果，使后续效果可读取实际伤害 |
| `HealthChangeSkillEffect.gd`、`CombatValueResolver.gd` | 统一伤害、防御、生命与仇恨结算 | 所有层级沿用统一结算，暴露已有返回的实际扣血量，不另写伤害公式 |
| `StatusEffectComponent.gd` | 当前仅存属性修正，不支持查询命名状态 | 在原组件增加独立的命名限时状态记录；不挪用属性枚举表示灼烧 |

不采用「每种箭写一个继承自投射物的专用脚本」；也不把所有投射物改造成任意递归规则图。当前仅增加两种可复用命中后效果：生成目标追踪子投射物，以及条件式附近目标伤害。

## 3. 内容结果与命中语义

1. 爆裂箭矢只有一次技能释放和一次正常冷却。生成的碎片不是新的技能施放，不消耗技能槽、冷却或专注，也不占用角色动作。
2. 主箭发射后即按既有技能规则视为成功释放；爆发序列可继续。之后任一层未命中、没有合法目标或伤害为零，都不倒退释放序列。
3. 主箭只有命中存活敌人且实际扣血大于零，才从**主箭命中位置**选取最多三个附近敌人，各发射一枚碎片。主箭原受击者不参与这一轮碎片目标筛选。
4. 每枚碎片有独立飞行与命中。碎片命中前读取受击者的灼烧状态，保存本次命中前快照；随后结算碎片自身伤害。仅在实际扣血大于零且快照显示有灼烧时，以碎片受击者为中心，筛选附近最多三个其他敌人，各结算一次追加伤害。受击者在碎片命中后死亡也不抹去已成立的条件。
5. 追加伤害是**即时范围目标结算**，不是第三代真实投射物；可单独播放飞溅视觉，但视觉不参与命中判定。它不触发该碎片的后续效果，也不再生成碎片。
6. 单次附近筛选内按实例去重；不同碎片的筛选彼此独立，允许再次命中同一敌人。理论最大伤害事件数为 `1 + 3 + 3×3 = 13`，实际数量取决于目标、飞行、状态、防御和生命。零伤害事件不计入未来连击评分。

第一次验证建议：两轮筛选半径均为 3 米；主箭基础伤害 10、攻击力倍率 0.6；碎片基础伤害 3、倍率 0.25；追加伤害基础值 2、倍率 0.1；技能冷却 7 秒。三个「最多 3」为此技能的内容定义，可在通用效果节点中配置，不是引擎硬编码。数值需通过真实战斗验证再调。

## 4. 复用组件与边界

### 4.1 两参数投射物交付适配

新增 `ArcProjectileDeliveryConfig`，由现有 `SkillDeliveryRunner` 识别。配置引用一个使用 `TrackingArcProjectile.gd` 契约的 PackedScene，运行时调用 `launch(target, start_position)` 并接收 `projectile_hit(target, position, direction)`。首个目标仍来自 SkillBase 的既有目标解析，不重新发明选敌。适配器在命中时再次核验目标存活、敌我关系与可选取状态，然后应用本次效果序列。未命中或超时不应用效果。

每次交付创建独立的 `ArcProjectileDeliverySession` 运行节点；根技能原有 Runner 负责启动与转发会话状态，不用自身唯一 `_busy` 字段长期锁住所有在途箭。生成的每枚碎片也各有独立会话。这样同一技能重复释放、三枚碎片并行飞行以及其他技能交错释放都不覆盖彼此的上下文。原火球八参数交付继续按旧路径工作，本期不强迫火球迁移。会话结束或失败时回收自身；一个子会话失败不取消已发出的其他碎片。

会话持有施法者引用、原技能请求身份、伤害仇恨倍率、命中效果节点和受击来源快照；这些是运行时数据，不写入共享 Resource。主箭释放后施法者动作结束或被打断，不取消已经发射的箭与碎片；单位／场景卸载时会话安全退出。未来爆发归属标识沿同一上下文传到每个子会话，保证迟到伤害只归属于原爆发，不由碎片重新申请爆发身份。

### 4.2 每目标命中结果

新增轻量的 `SkillHitOutcome` 运行时对象，记录本次直接命中的目标、位置、命中前状态快照、实际扣血量及原请求身份。每目标效果循环开始时创建一个对象，通过 `SkillDeliveryResult.current_hit` 交给现有 `SkillEffectBase.apply(context, result, target)`；后续效果只读本目标的结果。`HealthChangeSkillEffect` 继续调用 `CombatValueResolver.apply_damage()`，但不丢弃其返回值。效果按顺序执行：先伤害，再读取本次结果的后续效果。治疗效果维持原行为，不被错误计入伤害。保留 `apply()` 的布尔成功约定和三个参数，不要求每个既有效果修改签名。每个目标及每个并行会话使用独立结果，避免交叉覆盖。

一个真实正数扣血只产生一个可供未来评分消费的伤害事件；主箭、碎片和追加伤害分别记录，不能因视觉或多个信号重复计数。命中后效果的触发依据本会话的直接命中结果，不订阅全局伤害事件，避免追加伤害重新触发自身。

### 4.3 附近目标筛选

新增通用的附近目标查询：给定施法者、世界中心点、半径、敌我关系、最大数量、排除对象，在**触发时**而非技能按键时取得场上候选，复用 `TargetResolver.is_candidate_valid()` 完成关系、存活和可选取校验。以水平距离排序、实例 ID 作为同距离稳定次序；取前 N 个，不作随机投点。筛选结果只对本次动作去重，不在主箭与各碎片之间维护隐藏的全局命中排除表。

火球现有物理范围查询可作为实现参考或抽取公共查询 helper；改造后必须保持 Firebolt 当前的撞击与爆炸测试结果。查询不要求敌人预先进入施放时的 `candidate_targets` 快照，因为碎片抵达时场上敌人可能已经移动或死亡。

### 4.4 两类通用命中后效果

`SpawnNearbyArcProjectilesEffect` 是 `SkillEffectBase` 子类：仅在本目标直接命中产生正数实际伤害后工作；配置筛选半径、数量、敌我关系、排除当前受击者、子弹场景及子弹命中效果配置。可选的要求状态为空时不检查状态。它只发射子投射物，不自己结算碎片伤害。

`ConditionalNearbyHealthChangeEffect` 是 `SkillEffectBase` 子类：配置状态要求、筛选参数、伤害／治疗操作、基础值和攻击力倍率；本例设为“受击者命中前有灼烧、直接伤害大于零”后，对筛选目标逐一通过统一数值入口结算伤害。不向自身重新派发命中后效果。它是终端效果；状态要求为空时可表达无条件飞溅，操作为治疗时必须明确设置友方关系并按实际治疗量触发，不把治疗误报成伤害。

两个效果都不包含 `ExplosiveArrow`、`Archer` 或 `Burning` 的硬编码判断。它们的公开参数和所有新增 `@export` 字段须依项目规范在声明旁提供简体中文用途、单位、默认行为和影响范围说明。非法半径、数量、缺失 PackedScene、无效状态资源引用等在 Inspector 给出配置警告，运行时安全失败；“不要求状态”是合法且明确的空配置，不静默发出不完整攻击。

### 4.5 灼烧状态

在现有 `StatusEffectComponent` 内增加与属性修正并列的命名限时状态记录，按状态资源身份查询 `has_status()` / `get_status_stacks()`；同一状态默认刷新时长，最大层数由状态定义限定，死亡时清理。新增通用 `ApplyStatusSkillEffect`，供 Firebolt 或其他技能在直接命中并造成正数实际伤害后施加状态。正式 `BurningStatus.tres` 为数据而非逻辑类；首轮配置持续 4 秒、上限 3 层。爆裂箭只查询“是否至少 1 层”，不改变或消耗层数。

本文交付范围内的灼烧承担**可查询的命名状态和联动触发**；灼烧持续跳伤及炎爆按层增伤属于火法技能内容的后续设计，不在爆裂箭实现时偷加规则。若后续需要持续伤害，应增设可复用的周期伤害状态行为，而不是把伤害计时写进爆裂箭或 `StatusEffectComponent` 的灼烧特例。创建任何正式 `.tres` 必须经 Godot `ResourceSaver`／编辑器正式保存并验证有效 UID、强类型与 Inspector Quick Load。

## 5. 策划最终配置方式

策划以现有的「技能场景直接子效果」工作流为主，不需要学习规则图语言或分别创建检查对象、筛选器、数量三个资源。建议交付以下可复用装配：

```text
Archer/ExplosiveArrowSkill.tscn             ← 装入 Archer 常规技能槽
  Delivery = ArcProjectileDeliveryConfig
    projectile_scene = ExplosiveArrowProjectile.tscn
  DamageEffect: 10 + 0.6 × 攻击力
  SpawnNearbyArcProjectilesEffect
    触发 = 本目标实际伤害 > 0
    半径 = 3m，最多 = 3，关系 = 敌方，排除 = 主箭受击者
    child_projectile_scene = ExplosiveFragmentProjectile.tscn
    child_hit_profile = ExplosiveFragmentHitProfile.tscn

ExplosiveFragmentHitProfile.tscn            ← 可由其他技能重复引用
  DamageEffect: 3 + 0.25 × 攻击力
  ConditionalNearbyHealthChangeEffect
    触发 = 碎片直接伤害 > 0 且受击者命中前有 BurningStatus
    半径 = 3m，最多 = 3，关系 = 敌方，排除 = 碎片受击者
    追加伤害 = 2 + 0.1 × 攻击力

ExplosiveArrowProjectile.tscn               ← 复用 TrackingArcProjectile.gd，仅配轨迹与视觉
ExplosiveFragmentProjectile.tscn            ← 同脚本，配置更短航时、碎片视觉
BurningStatus.tres                          ← 状态数据；Firebolt 配 ApplyStatusSkillEffect
```

`ExplosiveFragmentHitProfile.tscn` 是效果配置容器，不是另一个 `SkillBase`，不装技能槽，也不具有冷却或 AI 释放条件。Profile 及其效果节点必须为每次子会话实例化，禁止共享可变运行状态。美术场景只提供动画、材质、特效和飞行表现；停止播放特效不能取消已成功结算的伤害。具体目录可按项目现有 `SkillSystem/00-Skills`、`Item/Projectiles` 和 `Effects/Skills` 分类，避免把内容资源塞进通用代码目录。

| 类别 | 交付物 | 验收内容 |
| --- | --- | --- |

| 通用效果 | 生成附近目标追踪投射物、条件式附近数值变化、施加命名状态 | 三类效果只依赖配置和公共接口，不含技能名分支 |
| 状态层 | 命名限时状态、BurningStatus 正式资源 | 层数、刷新、到期、死亡清理、有效资源 UID 与 Quick Load |
| 内容资源 | 爆裂箭技能、主箭/碎片视觉场景、碎片命中 Profile、火球灼烧配置、差异化命中/分裂/燃烧视觉 | Archer 两技能槽中的本技能可自动施放；火球先命中时能触发联动 |
| 验证 | 单元、集成和独立技能／特效测试场景 | 0、1、3、超过 3 个邻近目标；无灼烧/有灼烧；目标途中死亡；最大 13 次伤害；同技能重叠施放；正常 AI/显式施放 |
| 文档 | 策划配置说明、组件接口和限制说明 | 明确 Inspector 字段、触发顺序、复用边界；不需阅读实现脚本才可装配同构技能 |

独立测试场景可以新增测试单位夹具；不得由 Codex 向 `Scenes/TestScene.tscn` 添加或修改任何单位实例。若需要用户在 TestScene 观察新技能，交付时只说明应在 Godot 中手工将 Archer 源场景的技能槽装配到其现有单位实例，并提供必要位置和 Inspector 参数。

## 7. 复用边界与例子

| 后续需求 | 是否可不写新代码 | 复用方式 |
| --- | --- | --- |
| 同样「命中后裂为 N 枚，遇指定状态再溅射」的毒裂箭／雷裂箭 | 可以 | 复制或引用同一技能/碎片 Profile，改状态资源、数量、半径、伤害、文本与视觉；对应状态先须存在 |
| 无条件碎片飞溅或改为只对两名敌人飞溅 | 可以 | 状态要求置空，调整数量；不改规则脚本 |
| 改成直线弹道、穿透多个敌人、碰墙反射 | 不可以直接仅改美术 | 当前 Arc 只有目标抵达规则；要新增通用飞行/命中类型，再由技能配置选用 |
| 按暴击、破甲、击杀触发碎片 | 当前不可以 | 要先有这些通用事件或条件，不能在具体箭脚本写 if 特例 |
| 灼烧具备周期伤害、炎爆按层数增伤 | 当前不包含 | 增设通用周期效果或读层增伤效果，再配置到火系技能；爆裂箭链本身无需改动 |

“只换描述、美术、特效即可复用”成立的前提是**目标筛选、触发条件、后续行为属于已交付的这套规则语法**；若玩法改变了飞行/判定或引入全新条件，仍需先做一次可复用的通用扩展，不能承诺任意技能都零代码。

## 8. 测试和阶段边界

先锁定现有 Bow 普攻、Firebolt、SkillDeliveryRunner 和状态修正测试作为回归基线；再依次验证 Arc 适配、并发会话、实际伤害结果、附近筛选、状态查询、主箭生成碎片、碎片条件伤害及真实角色装配。测试必须以真实 Godot 场景加载与运行结果为准，不以静态文本检查代替。正式 `.tres` 的有效 UID 是契约测试的一部分。

设计审阅通过后另写实施计划，再进入代码与资源制作。当前文档不表示这些接口、技能、状态、视觉或测试已经实现。
