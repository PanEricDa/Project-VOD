## 1. 目的与不可改变的边界

阶段二已经让玩家通过1—4调用伙伴，并正确处理动作衔接、目标、专注与重复费用。阶段三让这些独立调用的实际伤害形成可接续、可结算、可再次开始的一轮连携。

可观察循环：

常规有效伤害积累专注 → 调用伙伴 → 第一笔连携正伤害开窗 → 后续伤害接续 → 间隔超时结算 → 新请求开始下一轮。

必须保留：

- 不新增全队技能串行队列，不改变伙伴独立执行、单伙伴一条缓存或已有动作锁。
- 窗口管理实际伤害，不管理技能释放顺序；施法特效和释放成功都不是伤害。
- 不改变普通AI、目标选择、仇恨、技能冷却、专注收益、伤害数值和已有费用提交/退款。
- 连携窗口没有整轮总时限；只有距最后一笔有效连携伤害的间隔。
- 闭窗不取消已受理请求，不等待全部投射物、碎片或缓存结束。
- 达分只在闭窗后发出终结资格事件；不暂停、不拦截输入、不弹终结窗口、不制作终结技能。
- 不增加每技能评分组件、连携专用伤害算法、计分标签或第二套Delivery。
- 不向Scenes/TestScene.tscn添加或修改单位实例。首先交付独立继承预览，正式房间接入另经授权。

## 3. 方案与职责

已选方案：新增独立SquadChainRoundController，复用现有指令与UI。

比较：

- 扩展指令控制器：文件更少，但输入、账务、监听、窗口和评分集中到同一类，后续调参容易影响指令事务。
- 独立评价组件：增加一个可见节点，由明确引用连接指令源；可以独立测试轮次和评分，保持原技能执行边界。
- 全局战斗事件总线或新连携技能体系：涉及更广的现有模块迁移，本阶段不采用。

职责：

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| SquadChainCommandController | 输入、受理、费用、执行归属、请求清理 | 窗口时钟、连击、评分 |
| SquadChainRoundController | 当前轮次、合法伤害接收、伤害间隔、计分、闭窗结果 | 扣费、取消技能、目标选择、暂停战斗 |
| SquadChainCommandDisplay | 读取状态、显示专注与评价、短暂结果提示 | 计算费用/评分/剩余业务时间、分配轮次 |
| 阶段四终结导演 | 未来消费资格事件 | 本阶段不创建空壳或隐藏代理 |

评价组件只引用一个command_source。世界与队伍来源沿用该指令源，不再配置第二份玩家、伙伴列表、Focus或Pause引用。

## 4. 状态与轮次生命周期

业务状态只有三种。未装配/非法配置是可用性诊断，不增加玩家操作阶段。

| 状态 | 后台含义 | UI |
| --- | --- | --- |
| IDLE | 没有当前可接收新请求的轮次 | 无伤害倒数；可显示上一轮短暂结果 |
| PENDING | 已分配轮次，尚无有效正伤害 | 不展示伤害倒数；伙伴卡片仍正常显示等待/施法 |
| ACTIVE | 已有有效连携伤害 | 显示连击、评分与间隔倒数 |

关闭不是一个阻塞新输入的长期状态。内部完成结算后回到IDLE，单独保留最近一次只读结果。

### 4.1 首次请求与未命中批次

1. UI查询不分配轮次。
2. 指令真正受理路径调用acquire时，在无当前轮次的情况下分配新的全局单调正round_id，进入PENDING。
3. 同轮后续请求沿用该身份；预留、实际支付、重复费用仍由原指令组件和账本处理。
4. 没有任何伤害前，不启动评分窗口，不显示虚假的倒数。
5. 指令源报告该PENDING批次活动请求数为0时，清理该批次并通知原账本关闭。该通知包括根动作与根/子交付的原生命周期，不重新遍历技能猜测状态。
6. 空批次没有round_finished或终结资格；仅状态回到IDLE。受理中途失败且活动数归零也按此处理。

不增加第二个“首击等待超时”。原指令等待上限和交付生命周期负责执行边界；评价只回收已经自然结束的空批次。

### 4.2 首次有效伤害

先确认事件合法，再执行同一个内部事务：

- H增加1，D增加本笔实际伤害。
- 进入ACTIVE。
- 截止时间设为本笔事件战斗时间 + 本轮间隔。
- 计算分数、就绪状态，通知显示。

不能先展示窗口，再漏掉开启窗口的第一笔伤害。

### 4.3 后续伤害与关闭

ACTIVE期间有效伤害累计H/D并刷新截止时间。没有总时限；即使当前所有请求都已经完成，也等伤害间隔超时，而不是提前闭窗。

超过截止时间时：

1. 捕获纯值结算结果。
2. 内部先关闭评分入口、记录关闭水位并清除当前轮次，使外部回调不可能重开旧轮。
3. 调用原command_source.close_round(old_id)，只关闭费用批次的新登记资格，不取消Host请求。
4. 发出一次round_finished；达分再发出一次finisher_qualified。
5. 新请求可以进入更大的新round_id。新一轮重复次数为0。

对外通知携带原round_id和scene_scope_id。通知前先固定内部结果；同步回调造成世界解绑时，停止向已失效会话继续发送资格。

### 4.4 旧请求与新轮并存

旧请求保留原轮次。旧费用记录只在原请求仍使用时保留；最终清理由原SkillCommandRequest、指令控制器和账本完成。

例如：

- 轮次A超时，仍有A的投射物和缓存。
- 玩家新的有效请求进入轮次B，费用按B计算。
- A命中：正常伤害，不计分、不续窗、不改变来源，也不恢复专注。
- B命中：计入B并按规则开窗或续窗。
- A的缓存晚些释放：仍按A结算，不能被重新标成B或使用B的基础报价。

同一伙伴动作与缓存占用仍有效。新轮开始不会让原来满着的缓存槽凭空空出。

## 5. 伤害资格与去重

### 5.1 接收条件

接收时同时确认：

- 来自本组件观察的本世界真实UnitBase.damage_resolved事件，世代/世界身份有效。
- origin为CHAIN，actual_damage有限且大于0。
- round_id恰为当前PENDING或ACTIVE轮次，且没有超过关闭水位。
- request_id、source_instance_id、scene_scope_id匹配指令源已接受并成功释放的根请求。
- 来源队伍与原请求的队伍归属一致，受击目标为有效敌方关系。
- 本事件未被该评价消费者处理过。

普通伤害、终结、治疗、零伤害、未知来源、旧世界、旧轮次和未成功释放请求都不计分。

请求合法性在伤害同步接收时验证。不能等到帧末再查询当前活动技能或请求表：瞬发交付可能已经自然清理，届时会错误丢失真实命中。

### 5.2 两层身份

- event_id防止同一扣血事件被重复累计伤害、续窗。
- 命中键使用request_id + hit_id + target_instance_id，防止同一次真实命中的元素/效果拆分重复加连击。

对每笔通过去重的正伤害事件：

- D累计actual_damage。
- 命中键首次出现才令H增加1。
- 截止时间刷新到本笔有效伤害之后。
- 同一事件重复回调不增加H/D，也不刷新时间。

范围对5个敌人各命中一次是5连击。独立多段或碎片命中使用已有不同hit_id；同次命中的两笔元素扣血合计伤害，但只算1连击。

评价不重掷伤害、不读取面板攻击力、不计算过量击杀。去重集合只保留当前轮次，关闭即释放，不记录整局伤害历史。

## 6. 评分与终结资格

公式保持：

S = 100 × (H / H0 + D / D0)

- H为有效真实命中数。
- D为去重后的实际伤害总量。
- H0为正的连击换算尺度；D0为有限正的伤害换算尺度。
- H、D两项相加，不要求分别达标，不设单项封顶或连击递减。
- 内部使用浮点除法；不允许整数除法截断评分。
- S达到或超过100，本轮标为终结就绪。后台S可以继续增长。
- UI进度仅显示0—100%，不把后台评分限制为100。
- 达分时不暂停，只有ACTIVE闭窗才产生一次资格通知。

PENDING建立时捕获本轮间隔与H0/D0；Inspector运行中改值只影响下一轮，避免同轮伤害被不同尺度评价。非有限/非正配置给明确诊断并拒绝建立新评价轮次，不除零、不静默改写为其他平衡值；已有请求不因此被取消或重复退款。

阶段三没有终结资格库存、领取接口或模拟演出。finisher_qualified是携带结果的一次事实通知，后续由阶段四导演消费；本阶段只展示短暂结果并继续普通战斗。

## 7. 战斗时钟与同帧边界

### 7.1 唯一时基

评价组件持有本世界的正常战斗时钟，使用有限非负物理delta推进：

- 节点明确使用PAUSABLE语义。
- 释放强调、显式菜单暂停、未来终结暂停都不推进伤害间隔。
- 不使用Time.get_ticks_usec作为业务倒数，不复用UI的强调期间真实时间。
- 不用Engine.get_physics_frames差值计算经过秒数，因为暂停时物理帧身份仍可能变化。
- 内部统一为微秒精度的整数时间戳；delta累计保留小数残差，避免逐帧截断漂移。该精度及处理优先级属于内部实现，不export。
- 伤害接收、输入受理检查、UI剩余秒数均读取同一战斗时基。

### 7.2 确定的边界

本轮最后伤害时间为t，间隔为T，deadline=t+T：

| 新事件时间 | 结果 |
| --- | --- |
| 小于deadline | 当前轮接续 |
| 等于deadline | 当前轮接续，伤害优先 |
| 大于deadline | 先关闭旧轮；该旧轮事件不再计分 |

不设置宽限帧、网络容忍时间或按技能区分的补偿。

内部在物理帧开始统一推进时钟，本帧事件使用同一帧时间戳；帧末进行一次超时收尾。伤害入口和真实受理入口仍先检查严格超时，保证即使收尾尚未执行，也不会把迟到请求/伤害放回旧轮。具体调度由组件内部封装，不要求单位或策划配置处理顺序。

任何帧末回调都携带会话世代和目标帧身份；退出、解绑或重复调度后无操作。技术上的帧末收尾不等于等待在途交付。

### 7.3 报价与受理一致

peek必须无副作用：不分配轮次、不发结算信号、不修改账本。当前轮已经严格过期时，peek返回0，UI按新轮基础费用展示。

acquire执行真实请求时，先同步关闭过期轮，再建立新轮。闭窗先把内部当前轮次清空，再通知账本/UI，避免同步状态回调看到已关闭旧轮而显示round_closed。

由于处在同一线程、同一时基，报价与受理不能跨用不同轮次。原预留与最终收费校验仍全部保留。

## 8. 接口与数据流

### 8.1 评价组件对外接口

拟定接口名供实施计划固定，均需邻近简体中文参数说明：

| 接口 | 契约 |
| --- | --- |
| peek_current_round() -> int | 无副作用；0表示没有可供新请求加入的轮次 |
| acquire_round() -> int | 仅真实受理路径使用；返回有效正轮次或0表示不可用 |
| get_round_status() -> Dictionary | 返回纯值副本，不分配轮次、不返回内部表或Node/Request |
| round_state_changed(snapshot) | 状态/计分/业务倒数变化后的只读通知 |
| round_finished(result) | 只有曾ACTIVE的轮次结算；每轮最多一次 |
| finisher_qualified(result) | 达分轮次结算后最多一次；不拥有暂停或终结库存 |

status提供：绑定状态、业务phase、当前round_id、H、D、S、0—1显示进度、interval_seconds、remaining_seconds、finisher_ready及最近一次结果。result只保留round_id、世界身份、H/D/S、是否达分和关闭原因等纯值。

### 8.2 指令组件的最小扩展

保留set_round_source、close_round、request_activity_changed、scope_changed以及全部原费用/执行接口。

增加一个窄的只读身份查询，例如：

is_released_request(request_id, round_id, caster_instance_id, scene_scope_id) -> bool

查询原_records中仍在生命周期内的请求，确认已经成功释放、未失败且四项身份一致。不能把内部Request/ledger字典交给评价或UI，也不创建新的来源属性。

评价组件拥有轮次提供者注册。使用现有表现组件类似的弱引用所有权约定，拒绝同一指令源被两个评价组件接管；销毁/解绑只解除自己安装的回调，不能擦除另一所有者。指令组件不依赖SquadChainRoundController类型，仍接受公开轮次回调。

### 8.3 数据流

1. 原InputMap → 指令源 → peek/acquire轮次 → 原费用预留 → 原Host/AI执行。
2. 原Delivery/Effects → UnitBase实际扣血 → CombatDamageEvent → 评价。
3. 评价闭窗 → 原close_round关闭费用批次新登记 → 只读结果与资格信号。
4. UI读取原Focus、原伙伴状态和评价快照；不参与前三条事务。

先保持来源与执行正确，再展示反馈；UI缺失或隐藏不能改变业务结果。

## 9. 绑定、退出与内存边界

- 世界只从command_source.get_bound_scope及scope_changed获得；不另设世界/玩家引用。
- 绑定时扫描现有单位，监听同世界动态加入/退出；连接保存弱引用及世代，解绑显式断开。
- 来源/世界失效时丢弃评分，不为退出场景发终结资格，不改变Focus。
- 当前PENDING/ACTIVE轮由评价关闭；旧请求的执行和回收仍由原控制器负责。
- 保留单个当前轮次、单个最近结果、当前轮去重表和单调关闭水位；不保存无限闭轮集合、整局命中表或节点强引用。
- 原本释放的攻击在来源角色死亡后仍按身份快照处理，不能因为当前角色节点不存在就改变已发生事件归属。
- 评价组件移除后，已受理请求继续按原规则处理；新请求在缺少轮次提供者时使用原失败关闭反馈。旧阶段二预览仍保留自己的开发提供者，不被全局迁移。

验收要求同时覆盖重复绑定、世界重载、动态单位、同步回调重入和只移除评价组件。

## 10. Inspector与UI

### 10.1 评价组件只有四项导出

| 分组/字段 | 类型 | 开发默认 | 约束与作用 |
| --- | --- | --- | --- |
| Assembly / command_source | SquadChainCommandController | 空 | 关联本关卡指令源；不重复填写队伍 |
| Evaluation / damage_interval_seconds | float | 2.0秒 | 有限正数；正常战斗中的伤害间隔 |
| Evaluation / hit_score_scale | int | 20次 | 至少1；H0，控制连击贡献 |
| Evaluation / damage_score_scale | float | 500点 | 有限正数；D0，控制实际伤害贡献 |

这些数值仅用于首版流程验证，不是正式难度曲线。配置具有合理范围和邻近中文说明，当前轮使用捕获快照。内部时间精度、命中去重、轮次身份、接管标记均不export。

### 10.2 现有UI只增加一个评价引用

SquadChainCommandDisplay保留command_source，新增可空的round_source: SquadChainRoundController。两者分别代表执行状态和评价状态，不复制任何规则参数。

- round_source存在时必须与command_source属于同一绑定世界和同一指令源；错误装配明确告警并隐藏错误评价，不显示其他战场的数据。
- Focus从原command_source.focus_source读取，不新增第二份focus_source配置。
- 本阶段新增配置种类总计5项：评价组件4项、已有UI1项。每技能新增配置为0。

### 10.3 显示内容
